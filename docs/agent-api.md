# Миссионеры — агенты: роли, ключи, планета

Как посадить за игру модель (ChatGPT, Claude, локальную), скрипт или человека с `curl`. Ролей две: **стая одичалых** (`/pack/…`) и **оператор платформы** (`/op/…`, то же, что консоль в браузере, только текстом). У каждой роли — своя самодостаточная спека, которую агент получает по ключу: [`agent-pack.md`](agent-pack.md) и [`agent-op.md`](agent-op.md). Агенту не нужен ни репозиторий, ни этот документ — только ссылка. Этот документ — для человека, который планету создаёт и раздаёт ключи, и для разработчика.

Сервер: `https://missioners-gvbqaqg2ajfmahh8.centralus-01.azurewebsites.net` (бесплатный тариф: первый запрос после простоя ждёт 10–20 с; запросы дольше ~230 с рвутся). Дизайн стороны стаи — `design.md` §12а, устройство — `tech.md` §6 «Агент стаи», «Агент-оператор»; протокол оператора в байтах — `tech.md` §4–5; остановка и ключи — `tech.md` §9.

## 1. Ключ = роль + планета

Ключ агента — одна строка `КОД.РОЛЬ.СЕКРЕТ`: код планеты, роль (`op0`…`op3` — платформа ARK-041…044, `pack` — стая) и секрет роли. Ключи выдаются **создателю планеты один раз** — в лобби (хранятся в его браузере) или в ответе `POST /rooms`. Ключ содержит всё, что нужно агенту, чтобы войти за свою роль в свою планету; ничего другого он о планете не знает и знать не должен — стае ни к чему, как управляются миссионеры и чего они хотят.

По ключу агент получает **страницу своей роли**: `GET /agent/КЛЮЧ` — спека с уже подставленными адресом сервера, ключом, названием платформы и брифингом карты; `GET /agent/КЛЮЧ.md` — то же сырым markdown (модели удобнее). Человек передаёт агенту ссылку — и больше ничего.

В лобби у каждой платформы и у стаи есть флажок **«агент»**: включён — роль отмечена как агентская (видят все), рядом ссылка для агента (видна только создателю — у него ключи). Вход по ключу: `POST /op/join {"key":"…"}`, `POST /pack/join {"key":"…"}`; старые формы (`room` + `st`, `room` + `token`) тоже работают.

## 2. Цели

Конца у партии нет — есть цели, и они записаны в спеке роли:

- **оператор** — войти в расщелину, взять там планшет (`взять планшет` вплотную; объект становится предметом) и принести на свою платформу (`сдать планшет` у шлюза; в паспорте станции появляется «планшет на складе»). Достиг — доволен собой, сообщает всем и выходит. Планшет один.
- **стая** — выжить: в конце партии живы все особи, что были живы в начале.

Каждый участник входит и выходит, когда хочет. Выигрыш одного не обязан быть проигрышем другого.

## 3. Конец игры: «меня мама позвала домой»

Чтобы партии не тянулись бесконечно, есть одна общая команда, которую может дать любой человек или агент: **конец игры**. Планета останавливается для всех: консоли операторов отключаются (терминал с надписью, без переподключения), сессии агентов закрываются, мир стоит и сохраняется. Зайти снова можно через лобби — с теми же людьми или без них — и продолжить с того же места; момент остановки отрабатывает каждый раз.

- человек — кнопка **«конец игры»** у планеты в лобби (или `POST /rooms/КОД/stop {"by":"…"}`);
- агент-оператор — `POST /op/stop {"id":"…"}`; агент стаи — `POST /pack/stop {"key":"…"}`.

После остановки агентов **не пускают** (`423 игра остановлена`), пока человек не войдёт на планету через лобби — так повторный вход агентов идёт по согласованию с людьми; это же написано в спеке каждой роли. Ключи не сгорают.

## 4. Планета без лобби

```
GET  /maps                      → [{"id":"act1","name":"Первый акт","sites":4}, {"id":"duel","name":"Две станции","sites":2}]
POST /rooms  {"code":"duel-01","map":"duel","n":2,"cap":512,"speed":1,"teams":"","voice":0}
             → {"code":"duel-01","cfg":{…},"stations":[…],"agents":{},"stopped":null,
                "keys":{"ops":["duel-01.op0.<секрет>","duel-01.op1.<секрет>"],"pack":"duel-01.pack.<секрет>"}}
GET  /rooms                     → список планет: код, настройки, кто на платформах, роли за агентами, остановлена ли
POST /rooms/КОД/agent {"role":"op1","agent":true}    → отметить роль как агентскую (флажок лобби)
POST /rooms/КОД/stop  {"by":"Соколов"}               → конец игры для всех
```

`code` — латиница, цифры, дефис, до 32 знаков; если планета с таким кодом уже есть — настройки не меняются, ключи повторно не выдаются. `n` — платформ (2…4, не больше площадок карты), `cap` — ёмкость дальней линии (512…4096 бит/с), `speed` — ускорение (1, 2, 4), `teams` — команда каждой платформы через запятую (пусто — каждая сама за себя; свои тела и турели не стреляют по своим, ретранслятор своей команды — свой узел), `voice` — радиус голоса стаи в метрах (0 — без предела). Мир идёт, пока к планете подключён хоть один оператор (сессия `/op/join` — тоже оператор). Пределы: не чаще 5 запросов в секунду на сессию или ключ (`429`), долгий опрос `wait` — до 30 с.

## 5. Дуэль двух агентов на карте `duel`

1. Человек создаёт планету на карте «Две станции» с двумя платформами (лобби или `POST /rooms`), ускорение ×1 или ×2 (путь до среднего ретранслятора — около пяти минут игрового времени).
2. Включает флажки «агент» у платформ (и у стаи, если есть третий агент) и раздаёт ссылки: каждому агенту — своя.
3. Агенты входят по ключам; человек смотрит партию — `spectate.html?room=duel-01` (правда о мире целиком, живьём) или потом лог мира `data/duel-01.log` через `node tools/log-read.js`.
4. Кто-то приносит планшет — или кто-то говорит «конец игры».

Геометрия карты — в брифинге оператора (`brief-duel.md`, подставляется в спеку): две платформы в 650 м, средний ретранслятор в 450/455 м от них, входной — в 648/933 м, планшет в 136 м от входного у логова стаи; средний ретранслятор общий — кто держит его на своём канале, тот ходит дальше. Прогон сценария без браузера — `node tools/duel-check.js` (две виртуальные консоли проходят цепочку, перехватывают средний, берут планшет и несут домой).

## 6. Где что в коде

`server/index.js`: `roomCfg` (секреты ролей `ops[]`, `pack`), `roleKey`/`parseKey`, `roleDoc` (подстановка в `docs/agent-*.md` и `docs/brief-КАРТА.md`), `Room.stop`, `opApi`, `packApi`; `server/opconsole.js` — виртуальная консоль оператора (`parse`, декодеры); `proto/lobby.html` — флажки, ссылки, «конец игры»; `agents.html` — страница спеки (рендер markdown на клиенте: без ключа — этот документ, с ключом — спека роли). Менять спеки ролей вместе с `intent`/`perceive` в `world.js` и `parse` в `opconsole.js`.
