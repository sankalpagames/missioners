# Миссионеры — техническая спецификация канала и движка

Описывает то, что реализовано в `proto/`, и то, куда это должно вырасти. Числа — из кода; если код и документ расходятся, прав код, документ надо поправить.

## 1. Архитектура: три изолированных слоя

```
┌──────────┐   байты    ┌──────────┐   байты    ┌──────────┐
│   МИР    │ ─────────► │  КАНАЛ   │ ─────────► │ КОНСОЛЬ  │
│ world.js │ ◄───────── │ link.js  │ ◄───────── │console.js│
│ (Worker) │  команды   │          │  команды   │          │
└──────────┘            └──────────┘            └──────────┘
      │ физика линии (расстояние, препятствия, мощность) ─► канал
      │ несущая есть/нет по каждому миссионеру           ◄─ канал
```

- **Мир** — симуляция в Web Worker. Не знает о консоли. Наружу отдаёт только байтовые сообщения `{id, cls, kind, unit, payload}` и физическую правду о линии (расстояние миссионера от станции, затухание в препятствиях, мощность его передатчика).
- **Канал** — единственный путь из мира в консоль. Очередь, ёмкость, потери, планировщик. Обратный путь (команды) тоже через него.
- **Консоль** — видит только сообщения станции: доставленные пакеты, потери и показания своего модема. Всё на экране восстановлено из этих пакетов. Отладочная шторка показывает правду о мире, если станция её отдаёт (только в одиночной игре), и помечена как «игрок этого не видит».

Честность — свойство архитектуры, а не дисциплины: консоль физически не может показать то, что не пришло.

**Станция** (`station.js`) — мир + канал в одном хосте, наружу только сообщения. Хоста два, консоль разницы не видит:
- `station-worker.js` — Web Worker, одиночная игра и лаборатория: грузит текст мира по сети и гонит такты сам;
- `server/index.js` — Node на сервере, сетевая игра (`index.html?room=КОД`): комната = станция, один канал на всех операторов комнаты, WebSocket `/ws?room=`. Раздаёт `proto/` статикой (кроме редактора), мир идёт только пока в комнате есть операторы.

Мир в обоих хостах грузится одним способом — текстом через `new Function` с шимами воркера (`self`, `importScripts`, `postMessage`, таймеры), как в headless-проверках `tools/`; `world.js` о хосте не знает.

Сообщения консоль ↔ станция:
- вниз: `{t:'pkt', n, at, msgId, kind, unit, seq, total, bytes, size, latency}` — доставленный пакет, `n` — сквозной номер доставки (по нему сервер досылает пропущенное), `at` — время станции; `{t:'drop', …, reason}`; `{t:'modem', at, speed, up, cap, orbit, qbg, qcmd, ncmd, retry, sec, cnt, queue[]}` — раз в секунду игрового времени, показания модема оператора (ёмкость, очереди станции, ETA запросов, статистика секунды для графика «Канал»); при отладке — ещё `dbg` (положения тел, существо, физика линии по телам, конфиг канала);
- вверх: `{t:'up', bytes}` — байты команды (§4); `{t:'speed', v}`, `{t:'autonomy', unit, v}`; сетевой хост — ещё `{t:'hello', since}` при (пере)подключении, ответ `{t:'welcome', operators, replay, at, speed}` и досылка пакетов с `n > since` (помечены `replay:true`); только при отладке — `{t:'cfg', k, v}`, `{t:'tp'}`, `{t:'peek'}`. `load`/`save` в сетевом хосте от клиентов не принимаются: мир — у сервера.

Показания модема — не игровые пакеты, а то, что терминал оператора знает о собственной линии; по каналу они не идут и байт не стоят. Часы консоли идут за станцией: поправка из `modem.at`.

## 2. Канал: два плеча

**Плечо 1, локальное** — радио миссионер ↔ станция. Физика по каждому миссионеру.

```
FSPL(d)  = 20·log10(d) + 20·log10(f_МГц) − 27,55         f = 430 МГц
SNR      = P_tx + G_мис + G_ст + G_доп − FSPL − L_преп − N
           P_tx  = −10…+10 дБм (регулируется, ест заряд)
           G_мис = −5 дБи (имплантированная антенна), G_ст = +6 дБи
           G_доп = +6 дБ после включения усилителя ретранслятора
           L_преп: расщелина — 8 дБ у входа + 22 дБ·глубина (доля пути вдоль дна; стены перекрывают прямую видимость)
           N     = −92 дБм (тепловой −130 + NF + помехи от реактора)
C_лок    = B · log2(1 + SNR_lin) · 0,5 · (FEC ? 0,5 : 1)   B = 4 кГц
           ниже SNR = −5 дБ несущая не захватывается: C = 0
BER      = 0,5 · erfc(√SNR_lin)   с FEC: SNR + 5 дБ
PER(n Б) = 1 − (1 − BER)^(8n)
```

Каждое удвоение расстояния — −6 дБ. Ориентиры: у шлюза SNR ≈ 44 дБ; вход в расщелину ≈ 10 дБ; середина ≈ 4 дБ (без FEC пакеты бьются на 90 %, с FEC — проходят); глубина ≈ −11 дБ — связи нет.

**Плечо 2, дальнее (СВС)** — станция ↔ оператор. Расстояние не влияет, ёмкость фиксированная: **512 бит/с** (ползунок 64…16000 в отладке). Битовые ошибки 1e-7. Опционально окно видимости ретранслятора (для варианта без СВС) — по умолчанию выключено.

Пакет считается доставленным, когда прошёл оба плеча: у станции буфер (store-and-forward). Потери считаются по локальному плечу для пакетов миссионеров и по дальнему для пакетов станции.

## 3. Пакеты и планировщик

```
заголовок 8 Б: msgId(2) kind(1) unit(1) seq(2) total(2)
полезная нагрузка ≤ 64 Б
```

Классы:
- **bg** (подписки) — очередь по ключу `unit:kind`, хранит одно сообщение: свежее вытесняет недоставленное старое. Исключение — кадры (`IMG*`, `IMD*`): пока предыдущий кадр не ушёл целиком, новый не принимается («кадр пропущен: предыдущий ещё передаётся»), иначе дельты теряют опору.
- **cmd** (ответы на команды) — FIFO. Потерянные пакеты повторяются через RTT (ARQ, до 6 раз). Пакеты миссионера вне зоны пропускаются (нет head-of-line blocking по нему), остальное — строго по порядку.

Такт 100 мс. Подписки идут раньше команд, но не больше 40 % полосы в секунду — команды не голодают. Среди подписок пульс станции всегда первый, остальные — по кругу (round-robin по ключам), и планировщик ждёт бюджета на пакет во главе очереди, а не обгоняет его мелкими: иначе при пяти телах с секундной телеметрией (120 Б/с при ёмкости 64) пульс станции не получал слота никогда. Бюджеты — token bucket: дальний и по одному на миссионера; ведро не копит ёмкость, пока канал молчит (max 0,3 с), но вмещает минимум два пакета — иначе большой пакет на слабой линии не уйдёт никогда (реальный баг, найден в прототипе). Порядок в такте: подписки → команды.

Вверх (консоль → мир): команды 3…7 байт, задержка RTT/2 = 0,3 с, требуют живого дальнего плеча. Направления независимы (как две линии, а не одна общая полоса): полоса вверх не моделируется — команды ничтожны, вниз идёт всё остальное. Забитая очередь вниз не мешает отправить команду; она задерживает только *ответ*. Индикатор занятости — лампа у вкладки «Канал»: зелёная — очередь пуста, жёлтая — есть, красная — больше 10 с ожидания.

## 4. Протокол вверх (команды)

| код | байты | смысл |
|---|---|---|
| 1 | `[1,0,unit]` | описание (нужно живое тело) |
| 2 | `[2,tilt+90,unit]` | лидар; наклон лучей −45…+45° к горизонту (0 во втором байте — горизонт, старый формат). Наклон запоминается и используется автосъёмкой |
| 3 | `[3,level,unit,delta]` | кадр: уровень 0…3, дельта 0/1. `unit=0` — камера шлюза (стационарная, у станции) |
| 6 | `[6,0,unit,xh,xl,yh,yl]` | идти в точку; тело идёт и смотрит туда. Цель дальше радиуса возврата (§6, «Граница») станция не принимает — событие 28 |
| 7 | `[7,mode,unit]` | режим 1…5 |
| 8 | `[8,objId,unit]` | взаимодействовать: подойти и выполнить действие для текущего состояния объекта |
| 9 | `[9,dBm+20,unit]` | мощность передатчика (−10 / 0 / +10 дБм; в игровом интерфейсе — в панели тела) |
| 10 | `[10,mask,0]` | вырастить: bit0 камера, bit1 лидар |
| 11 | `[11,0,0]` | статус станции: паспорт текстом (`INFO`) + пульс. Этим же начинается сеанс |
| 12–14 | `[k,interval,unit]` | подписки: телеметрия / лидар / описание, 0 = выкл |
| 15 | `[15,interval,0]` | пульс станции |
| 16 | `[16,interval,unit,level,delta]` | автосъёмка; `unit=0` — камера шлюза |
| 17 | `[17,0,unit]` | стоп (цель остаётся) |
| 18 | `[18,0,unit,xh,xl,yh,yl]` | смотреть: повернуть голову к точке, не идя |
| 19 | `[19,objId,unit]` | изучить: подойти и доложить состояние объекта |
| 20 | `[20,itemId,unit]` | использовать предмет: 40 брикет → глюкоза +50, электролиты +20 |
| 21 | `[21,itemId,unit,dir]` | обмен со складом у шлюза (в 12 м от люка): dir 0 — сдать, 1 — взять; 42 — камера (датчик) |
| 22 | `[22,itemId,unit,objId]` | положить предмет в контейнер (подойти и сделать); objId 0 — сбросить на грунт: возникает «свёрток» (id 100–199) |
| 23 | `[23,itemId,unit,objId]` | взять предмет из контейнера |

Координаты — дециметры, смещение +32768, big-endian (16 бит: ±3276 м, шаг 0,1 м); в пакетах вниз координата за пределом обрезается по краю, не заворачивается.

## 5. Протокол вниз (виды сообщений)

| kind | класс | размер | содержимое |
|---|---|---|---|
| `TLM` | bg | 16 Б | пульс, электролиты, глюкоза, токсины, кожа, кости, психика, опасность, потребление, заряд, генерация, x(2), y(2), режим |
| `HB` | bg | 6 + 5n Б | биозапас, камеры на складе, рост (с или 255), брикетов на складе, резаков на складе, n; по миссионеру: id, флаги (жив, несущая, камера, лидар, автосъёмка, у шлюза), заряд, предметы (биты 0–1 — число брикетов, бит 2 — резак), SNR+30 дБ — станция измеряет уровень сигнала каждого тела; без заряда передатчик молчит, несущей нет |
| `DESC` | cmd/bg | 4 + (5 + имя) Б × объект | x, y съёмки (2×16 бит); далее по объекту: id, класс (0 объект, 1 ориентир, 2 неопознанное, 3 тело, 4 миссионер), пеленг/2, дальность (м, ≤255), длина, имя текстом |
| `SONAR` | cmd/bg | 79 Б | x, y съёмки; наклон+90; высота датчика над уровнем станции (2 Б, (z+40)·10, шаг 0,1 м — барометр тела; шаг 0,5 м давал ступеньки между снимками выше сечения изогипс); маска «сплошное» 64 бита — поверхность вдоль луча круче 40° (`MAX_SLOPE`: корпус, обломки, стены расщелины, обрыв), измеряется на теле парой лучей; 64 луча, наклонная дальность/100 м × 255. Консоль проецирует на горизонталь по наклону. Координаты в пакете нужны, потому что к моменту доставки тело уже ушло на несколько метров |
| `IMG0…3` | cmd/bg | 64 / 256 / 1024 / 4096 Б | уровни пирамиды 8×8 → 64×64, 8 бит серого; запрос уровня k шлёт уровни 0…k |
| `IMD0…3` | cmd/bg | 2 + Σ(1 + (side/8)²) | дельта-кадр: `[frameNo, key, (idx, блок)*]`, сетка 8×8 блоков, уходят изменившиеся (порог 18) |
| `EVT` | cmd | 2 Б | код события, аргумент. 28 — отказ по ПС-2 (цель дальше радиуса возврата), аргумент — расстояние до ближайшего узла в десятках метров (≤255) |
| `INFO` | cmd | текст | паспорт станции: блок, состояние, возраст миссии, оператор, запасы, радиус возврата и число узлов («возврат: ПС-2, 500 м от узла; узлов 1»), задача |
| `CONT` | cmd | 2 + n Б | содержимое контейнера: id, n, предметы. Досылается после осмотра, вскрытия, положить/взять |
| `EXAM` | cmd | 4 + текст | id, 0, длина (2 Б), текст осмотра — составлен станцией из состояния мира |
| `ACT` | cmd | 4 + текст | id, код результата (0 сделано, 1 нечего делать, 2 нужен предмет, 3 условие не выполнено), длина (2 Б), текст |

Размеры с заголовками: телеметрия 24 Б, лидар 87 Б, описание 14 объектов ≈ 230 Б, осмотр ≈ 40–80 Б, кадр 32×32 пирамидой 1376 Б, 64×64 — 5536 Б, ключевой дельта-кадр 32×32 — 1234 Б.

**Текст по каналу.** Описания, осмотры и результаты действий — текст, составленный станцией из её базы знаний и текущего состояния мира (`nameOf`, `examText` в `world.js`): «тело М1», «существо, класс не определён» / «объект, класс не определён» (спит), «Не двигается. Камеры нет. При нём: резак». Ничего не перечислено заранее на стороне консоли. Кодировка однобайтовая, в духе КОИ-8 (`encText`/`decText` в `codebook.js`): кириллица, латиница, цифры, знаки — байт на символ. Многопакетные сообщения консоль собирает по `msgId` (`assemble`). Коды остаются только у системных событий (`EVT`), режимов и предметов — это протокол, а не мир.

**База знаний станции** (`codebook.js`) живёт в мире: логика состояний и шаблоны текста. Консоль берёт из файла только кодек текста, коды событий, режимов и предметов. Типы 1…7 — ориентиры, 10…33 — объекты (32 планшет, 33 свёрток), 250 — неизвестный, 251 — тело миссионера, 252 — живой миссионер. У типа: `states[]` — текст по состояниям (ответ на «изучить»), `actions[]` — `{from, to, verb, item?, needs?, req?, fail?, special?}`: переход состояния, глагол для журнала, выдаваемый предмет, требуемый предмет, требуемое состояние другого объекта, текст отказа. Предметы: 40 брикет, 41 резак, 42 камера (становится датчиком). Пример зависимости: резак (у входа в тоннель) → срастить кабель у мачты → включить усилитель (+6 дБ).

**Контейнеры.** Тип с полем `container: k` — контейнер, содержимое видно и доступно с состояния k (ящик — после вскрытия, груда — после разбора, камень с резаком, свёрток, тело — всегда). Мир хранит `contents[id]`; у тела содержимое — его предметы плюс камера (42). Передача между миссионерами — только через контейнеры (положить + взять), прямой передачи нет.

**Описание издалека** отдаёт только тип; подробности и изменения — через «изучить»/«взаимодействовать», которые требуют подойти (тело идёт к объекту, по прибытии выполняет — `pending`). Мир хранит `objState[id]`; консоль ведёт **журнал** по объектам — текст станции как есть: «М1 · ящик: Запечатан. Пломба цела.», «М1 · ящик: вскрыл. Вскрыт. Здесь: пищевой брикет.»

## 6. Мир

- **Уровень** (`level.js`, объект `LEVEL`) — данные первого акта, отдельно от логики: точка старта, ориентиры с подобъектами (тип, смещение, курс в градусах, начальное состояние, содержимое контейнера), колена и ширины расщелины, корпуса кроме платформы, лёжка и логово существа, сюжетные декорации. `world.js` строит из него `POIS`, `HULLS`, `objState`, `contents`, существо; `terrain.js` — расщелину, хребет и `FIXED`; производные пересчитывает `TER.reload()`. Правила видимости ориентиров по расщелине — из геометрии (`TER.inside`, `tunnelT`), а не по id. Файл пишет редактор (§11); комментарии-имена в нём восстанавливаются из кодовой книги. Свойства типов (спрайт, высота отражателя, радиус для лидара) остаются в `codebook.js` и `world.js`.
- **Рельеф** (`terrain.js`, объект `TER`) — одно поле высот `H(x,y)` в метрах: равнина с дюнами по ветру, посадочное поле у станции (плоско, пусто), хребет с позвоночником в 28 м за входом в расщелину (гребень 26–35 м, со стороны станции обрыв в три террасы и осыпь, с другой — пологий склон), **расщелина** — ломаная из пяти колен с тупиковым отростком (`LEVEL.canyon`, ширина 9 → 4,5 м), вырезанная в хребте до уровня дна; в конце — завал. `tunnelT(x,y)` — доля пути вдоль дна (0…1) или −1 снаружи: от неё считаются затухание радио, токсины и темнота. Тона грунта и породы, органические маты в низинах, процедурные декали плоских объектов (следы, борозды, гарь, кабель, вода) — там же. Дизайн местности — `design.md` §11б.
- **Декорации** (`TER.decor`): валуны двух видов, россыпи, сухостой, скальные выходы у подножия, останцы на дальней равнине — по хешу координат; сюжетные — списком в `LEVEL.decor`: завал в конце расщелины, поле обломков вокруг корабля, семь пирамидок по тропе от ящиков ко входу, восемь столбиков кабеля от станции к мачте. В кадр и в лидар попадают (`DECOR_R`: радиус футпринта в долях `Hs`, высота `Hs`; сухостой не отражает, столбик кабеля — 8 см), в описание и на карту — нет.
- Ориентиры с подобъектами (смещения из уровня; курс подобъекта, если задан, выбирает ракурс спрайта и направление декали); глубина расщелины (ориентир 7) и её подобъекты — на дне последнего колена. Препятствия: корпус платформы (эллипс `STATION`) и круги из `LEVEL.hulls` (обломки, r 4).
- **Миссионер**: позиция, курс (направление последнего движения), цель `goal`, движение `target`, режим, тело (несколько ОДУ: пульс → 60 + 55·нагрузка + 95·страх + 45·боль; глюкоза (0,003/с в покое, ×3 на ходу: ~9 ч / ~3 ч), электролиты, токсины в расщелине, психика от страха и темноты; заряд = (генерация − потребление)·0,01/с: ходьба с фонарём ~3 ч, стоя почти ровно, отдых восстанавливает; при 0 — смерть, приборы на мёртвом теле молчат), датчики, подписки, `lastImg` по уровням для дельт.
- **Камера** (`camera.js`, объект `CAM`): `camHeading` = на цель, если она есть и не достигнута, иначе курс. Поле зрения 50°, высота глаз 1,6 м. Кадр — рэймарчинг по полю высот (нормали → солнце снаружи, фонарь в расщелине, без фонаря — только ближний метр; дымка по расстоянию, дальние планы на небе), объекты и декорации — спрайты-билборды из атласа `sprites.png` (таблица `SPRITES` в `codebook.js`: лист из 5 ракурсов + зеркало, реальная высота в метрах; курс объекта выбирает ракурс; состояние подменяет лист: существо спит/стоит, миссионер стоит/идёт/тело), тени — контактная и от солнца — и декали по точкам земли. Рендер в удвоенном разрешении с усреднением, спрайты усредняются по футпринту пикселя. Пирамида и дельты рендерят кадр нужного размера (32×32 — ~60 мс, 64×64 — ~350 мс в воркере). Атлас собирается `tools/sprites-build.js` из raw-листов (в репозиторий не входят; id ассетов — `tools/spritecook-assets.json`); до загрузки атласа объекты — серые блоки. `renderRaw(u,W,objs,{H,fov,heading,z})` умеет кадр W×H с другим полем зрения, курсом и высотой глаз — для `tools/banner.js` (шапка лендинга, FOV 75, 480×120 ×3) и свободной камеры редактора; игра рендерит квадрат.
- **Столкновения**: тело (радиус 0,6 м) не идёт на склон круче 40° (`MAX_SLOPE`, tg = 0,84: стены расщелины, обрыв — нет; дюны, осыпь, завал — да) и не проходит сквозь корпус платформы и обломки; цель внутри корпуса (ориентиры «обломки», «шлюз» и их подобъекты стоят в центре) переносится на ближайшую точку снаружи со стороны тела, а не отвергается; при упоре шаг поворачивается на ±45°/±90° (скольжение); если за 4 с не приблизилось к цели на метр — стоп и событие «путь перекрыт». Поиска пути нет: расщелина проходится точками по коленам. Существо ходит без столкновений.
- **Лидар** (в коде и протоколе — `sonar`/`SONAR`, историческое имя): 64 луча с высоты `SONAR_H` = 1,7 м над грунтом (голова; глаза камеры — 1,6) под наклоном `u.sonarTilt`; луч (`castRay`) идёт по полю высот шагом 0,5 м с уточнением бисекцией, дальность наклонная. Бит «сплошное» — измерение, не подсказка мира: на каждый азимут второй луч на `SONAR_DT` = 3° выше, обе точки попадания лежат на поверхности, крутизна хорды между ними — уклон поверхности вдоль луча; хорда круче `MAX_SLOPE` (40°, куда тело не пройдёт) — «сплошное». Вертикальная стена вертикальна с любого азимута; склон, взятый наискось, кажется положе; объект, над которым второй луч прошёл, — не сплошной; второй луч без эха — не сплошное. Корпуса (`HULLS`: платформа — эллипс `STATION` из кодовой книги 16×9 м, обломки — круг) и объёмные объекты — по высоте отражателя (`OBJ_H`): луч выше объекта проходит. Наклон вниз даёт эхо от грунта на каждом луче — профиль рельефа; в панели грунтовые цепочки — тусклые линии, сплошные — яркие. Снимки из соседних точек ложатся на одну линию — расхождение в пределах шага квантования дальности (0,4 м).
- **Существо**: спит на дне последнего колена (338, 216), просыпается в радиусе обнаружения ближайшего живого миссионера (70 м с фонарём; 6 м в скрытности; 35 в отдыхе), идёт 1,1 м/с (0,7 к скрытному), бьёт каждые 2 с (кожа −12, кости −5), при трёх ударах в режиме «бой» уходит в логово за завалом на 120 с передышки, возвращается домой, если все дальше 160 м. Без столкновений.
- **Мёртвое тело**: остаётся, приборы работают на остатке заряда (утечка 0,004/с, 0,03/с при автосъёмке). Появляется в описаниях других как тип 251.
- **Взаимодействие**: шкаф усилителя (id 31) — +6 дБ ко всем линиям (требует срощенного кабеля, id 32, для которого нужен резак); обмен со складом — из консоли станции у шлюза (12 м); камера с тела — «взять» как из контейнера.
- **Граница мира** — не физика линии и не рельеф, а протокол станции ПС-2: цель (команды «идти», «изучить», «взаимодействовать», «положить», «взять») дальше `RETURN_R` = 500 м от ближайшего **узла** станция не принимает — событие 28 с расстоянием до узла; тело и голова остаются как были. Узлы: центр станции (`STATION`) и мачта ретранслятора (ориентир 3) после включения усилителя (`antennaBoost`) — ретранслятор раздвигает границу, как и обещано дизайном. Бюджет линии (дБ) к границе не привязан: за границей несущая ещё может держаться, но станция не рискует биоматериалом. Рельеф и координаты за границей по-прежнему определены (функция от координат), поэтому это единственная стена.
- **Несущая**: канал каждый такт сообщает миру, кого из миссионеров станция слышит и с каким SNR; миссионер сам это знает (физика) и по инструкции действует после 20 с тишины. Команды телу без несущей не доставляются (событие 25); мёртвому доступны только приборы (24); без заряда приборы молчат (26).
- Время: такт 0,1 с; ускорение ×1/×2/×4 применяется к миру и каналу одновременно.

## 7. Изображения: подтверждение кадра

Дельта-кадр опирается на последний кадр, который *реально ушёл*. Мир не знает состояния канала, поэтому:

1. мир рендерит кадр, кладёт его в `pendingImg`, шлёт `IMD`;
2. канал либо принимает (нет незавершённого кадра того же миссионера) и отвечает `imgAck ok=true`, либо отбрасывает и отвечает `ok=false`;
3. мир обновляет `lastImg` только при `ok=true`.

Для кадров по кнопке (класс cmd) очередь принимает всегда, `lastImg` обновляется сразу.

Консоль собирает кадр по пакетам; сборка живёт, пока приходят пакеты (90 с без пакетов — сброс). Блок, попавший на границу потерянного пакета, не применяется. Новая пирамида чистит холст, чтобы был виден прогресс; дельта — нет.

## 8. Консоль

- Состояние по миссионеру: телеметрия и история, трек, последний лидар, описание, кадр, подписки, цель, инструкция.
- **Лидар на карте**: снимок хранится с координатами съёмки и наклоном из пакета, дальности проецируются на горизонталь. Стены (сплошные отсчёты, соседние с разницей дальности < 0,5 м + 30 %, цепочки от 2) — светлые линии. **Карта высот**: из дальности, наклона и высоты датчика консоль считает высоту каждой точки попадания и копит её в сетке 2 м (среднее по ячейке, до 8 отсчётов веса). Сплошные отсчёты в карту высот не идут: точка на вертикальной поверхности — не высота грунта в этой XY (на одной XY все высоты от подошвы до гребня, и какая попадёт в пакет, зависит от наклона и дальности, а не от рельефа; раньше вдоль стены получалась ложная лесенка +0,5 м на каждые 6 м при +5°, и изогипсы этой лесенки шли поперёк стены). Несплошные попадания в объекты (ящик, тело) ложатся как грунт с высотой точки на объекте. Ячейки, через которые прошла стена (`hwall`, из сплошных пар каждого снимка), — граница: сглаживание через них не тянется (раньше высота дна уходила на 4 м под скалу), изогипсы в квадратах с такой ячейкой не строятся (иначе между ячейкой стены и гребнем ложилась пачка ложных изогипс). Реестр стен — в сохранении; старое сохранение без него восстанавливает стены из снимков. На карте — заливка тоном по высоте и изогипсы через 0,5 м по центрам ячеек (marching squares); отрезки собираются в цепочки, цепочки короче 4 отрезков не рисуются — на плоском их даёт ошибка измерения, а не рельеф. Точность проверяется `node tools/hmap-check.js` (маршрут станция → расщелина, все наклоны): ошибка ячейки 0,03 м (медиана), изогипса в 1 м от истинной того же уровня; увязка снимков по перекрытию проверялась и отвергнута — при барометре 0,1 м она только добавляет дрейф. Карта высот, ячейки стен и снимки — в сохранении (до 120 снимков). Низкое эхо (объекты) — только в панели, жёлтыми точками. Место объекта — из пеленга (шаг 2°) и дальности (шаг 1 м) описания, ошибка растёт с дальностью, поэтому для неподвижных объектов остаётся оценка с самой близкой съёмки (`range` в `known`); существо — всегда свежая. Подписи не налезают друг на друга: предмет уступает ориентиру и сдвигается вниз с выноской. Ориентиры (класс 1) — ромб с ножкой и имя прописными: это место; предметы, тела, существо — точка и имя строчными. Знак станции — контур корпуса `STATION` из кодовой книги, тот же, от которого отражается лидар. **Радиус возврата** — пунктирные круги вокруг узлов: радиус — из паспорта станции (`INFO`, строка «возврат:»), станция — всегда, мачта — после события 3 (усилитель включён) и если её место известно из описаний (`known`, id 3). Под картой — выключатели заливки и изогипс и срок показа пройденного пути (1/5/20 мин, весь); это только отображение, данные не трогает. Наклоны в списке: +5, 0, −1, −2, −3, −6, −12° — дальность до ровного грунта с 1,7 м ≈ 97/49/32/16/8 м.
- **Карта** — из телеметрии (треки, до 600 точек, кнопка стирания) и описаний (объект = координаты съёмки из пакета + пеленг + дальность; `seenBy` — кто видел, изученный или тронутый объект тоже становится знакомым). Покрытие описаний — единая область, последний снимок ярче. Холст в половинном разрешении, растянут на 7 % вширь. Клик — выбор (локально); двойной клик по миссионеру в шапке — перелёт к нему.
- **Расход по панелям** — скользящее окно 5 с по доставленным байтам каждого вида. Оценка под кнопкой «снять» — из размеров в §5 и текущей ёмкости.
- Данные старше порога приглушаются (`.stale`): тело — 3 интервала телеметрии, лидар и описание — 120 с, кадр — 300 с.
- Никакой логики мира в консоли нет; всё, что похоже на «знание», — кэш принятых пакетов.

## 9. Сохранение

`localStorage['missioners.save'] = {v, savedAt, world, console}` каждые 10 с (после открытия консоли) и при экспорте. `v` = `SAVE_VERSION`; при расхождении заставка предупреждает и советует новый сеанс.
- **Мир**: `snapshot()`/`restore()` в `world.js` — время, станция, состояния объектов, существо, миссионеры (без буферов кадров), усиление. `catchUp` есть, но при загрузке вызывается с 0: игровое время стоит, пока консоль закрыта; скрытая вкладка не пауза — мир в воркере продолжает идти.
- **Консоль**: `consoleSnapshot()`/`restoreConsole()` — время, активный, станция, счётчики, миссионеры (история до 600 точек, без буферов кадров), `known`, `journal`, содержимое контейнеров, снимки лидара, лог (400 строк).
- Управление сеансом — в терминале заставки, одной клавишей: `[r/enter] resume [n] new [i] import file [e] export file`; «new» переспрашивает `overwrite stored session? [y/n]`; Enter — первый вариант. Экспорт — тот же JSON файлом; импорт — записать в хранилище и продолжить. В консоли кнопок нет.
- После восстановления заставка всё равно проходит через реальный запрос статуса; очереди канала перед восстановлением сбрасываются (`link.reset()` в станции).

**Сетевая игра** (`?room=КОД`): мир хранит сервер — JSON на комнату в `DATA_DIR` (App Service: `/home/data`, иначе `./data`): `{v, savedAt, world, n, speed, ring}` — снимок мира, номер последнего доставленного пакета, ускорение и хвост доставленных пакетов (5000); запись атомарно через временный файл каждые 10 с, при уходе последнего оператора и по SIGTERM. Консоль хранит в браузере только своё знание (`missioners.save:КОД`, `world:null`) и `rxN`; при входе шлёт `hello {since:rxN}`, сервер досылает пакеты с бо́льшим номером — журнал, карта и кадры восстанавливаются из тех же байт. Меню сеанса в сетевой игре нет: местное знание подхватывается само, новый сеанс — новая комната. Ускорение ×4 — общее на комнату.

Отладка: `{t:'peek', unit}` → `{t:'peekImg', img}` — чистый рендер 64×64 мимо канала, только для шторки. `{t:'level', canyon, pois}` — мир шлёт один раз при старте: правда о мире для карты в шторке (расщелина, ориентиры); клик или перетаскивание по ней — телепорт (`{t:'tp'}`).

**Лаборатория лидара** — `index.html?lab`, только на localhost (на опубликованном сайте флаг игнорируется): та же консоль и тот же мир (`LAB` в `console.js` и `world.js`), но канал без ограничений (1e8 бит/с, шум −500 дБм, RTT 0, BER 0), заставка без меню сеанса, автосохранение выключено; клик по карте и стрелки (2 м, с Shift 10 м) — телепорт тела мимо канала с немедленным запросом лидара под выбранным наклоном; существо не просыпается, тело не умирает. Панели кадра, описания и команды скрыты. Датчик, пакет `SONAR`, карта высот и изогипсы — игровые.

## 10. Куда расти

- **Настоящий кодек**: рендер → реальное сжатие → длина буфера = объём передачи. Тёмный кадр сожмётся лучше шумного. Прогрессивность через реальный progressive JPEG или вейвлеты.
- **Состояния в кадре**: вторые листы для вскрытого штабеля, раскопанной насыпи, шкафа с индикатором; существо «бьёт». Сейчас в кадре меняются только существо (спит/стоит) и миссионер (стоит/идёт/тело).
- **Декорации в столкновениях**: валуны и выходы породы видны в кадре и в лидаре (крупные — «сплошное»), но тело проходит сквозь них; для честности — круги-препятствия по `DECOR_R` в `stepBody`.
- **Зум**: угол обзора как параметр запроса кадра (40° по цели / 60° обзор) при том же размере в байтах.
- **Параметры запроса кадра**: разрешение × глубина × сжатие → ожидаемый размер → время.
- **Другие клиенты** (телефон, терминал) поверх того же протокола станции (§1) — сервер уже есть.
- **Лобби**: список комнат (`GET /rooms` отдаёт коды и число операторов), страница входа, имя оператора. Второй шаг мультиплеера, см. `roadmap.md`.
- **Кодовая книга как прогрессия**: новые типы появляются, когда игрок их «определил» картинкой.
- **Возвращение миссионера**: физический слив всего записанного при контакте со шлюзом.
- **Вычисления на станции**: запросы вида «сосчитать движущиеся объекты в кадре» → байты + уверенность.

## 11. Редактор уровня

`editor.html` + `editor.js` в `proto/` — инструмент, не игра: читает уровень, рельеф, камеру и физику линии напрямую, канала и воркера мира нет (правило «консоль не читает мир» на него не распространяется). Работает **только с localhost** (проверка `location.hostname` в загрузчике страницы; на опубликованном сайте — подсказка), запуск — `python3 proto/serve.py` → `http://localhost:8765/editor.html`.

- **Карта**: вид сверху, пан/зум; карта высот считается по сетке отсчётов текущего вида (`TER.H`, шаг 3 px, тон по высоте + светотень от `TER.SUN`), красным — склон круче `MAX_SLOPE` (тело не пройдёт), изогипсы marching squares с шагом по масштабу (0,5 / 1 / 2 / 5 м), пачки изогипс на стенах не рисуются. Слои: высоты, изогипсы, непроходимое, процедурные декорации (`TER.decor`), сетка, радиус возврата (пунктир вокруг станции и мачты при включённом усилителе), подписи.
- **Объекты**: ориентиры (ромб, ПРОПИСНЫЕ), подобъекты (точка, курс — штрих), колена расщелины и отростка (квадраты, ширина подписью), корпуса, лёжка/логово существа, точка старта, сюжетные декорации (крестики). Перетаскивание двигает (ориентир — вместе с подобъектами; колено — с корнем отростка, если он на нём; ⇧ — шаг 1 м); клик — свойства: тип из кодовой книги, x/y и смещение, курс, начальное состояние, предметы, ширина колена, высота декорации. Добавление: подобъект (к выбранному или ближайшему ориентиру, не больше 10), ориентир (свободный тип 1…9), декорация, корпус, колено (двойной клик по расщелине или «колено после»). Удаление — Del. Отмена — ⌘Z/Ctrl+Z (снимки `LEVEL` в памяти).
- **Курсор**: координаты, высота, уклон, положение в расщелине (метры от входа, ширина, глубина и затухание), расстояние от станции и до выбранного, SNR/ёмкость/потери для тела в точке при 0 и +10 дБм — тот же `Link` с расстоянием и затуханием, как их считает мир; выключатель усилителя. Линейка — режим R: отрезок с длиной, Δh и пеленгом.
- **Свободная камера**: кадр рендерит воркер (blob, `importScripts` level + codebook + terrain + camera, без `world.js`) тем же `CAM.renderRaw`; сцена — весь уровень без правил видимости (спящее существо на лёжке, платформа, фигура миссионера в точке старта для масштаба, декорации). Камера и цель — на карте, перетаскиваются; размер 128×80…256×160, поле зрения, высота глаз, фонарь; стрелки — полёт (вперёд/назад, поворот), PgUp/PgDn — высота; «кадр на выбранное» ставит камеру в 8 м от объекта. Автосъёмка после каждого изменения, запросы во время рендера сливаются в один.
- **Сохранение**: `POST /level.js` в `serve.py` — принимается только с loopback и только если тело начинается с заголовка уровня; пишется атомарно через временный файл. Если сервер не принял — текст файла показывается для копирования. Сериализация детерминированная: несохранённый уровень воспроизводится байт в байт. «Перечитать» — перезагрузка страницы; несохранённые правки — предупреждение при закрытии.
