# Миссионеры — техническая спецификация канала и движка

Описывает то, что реализовано в `proto/`, и то, куда это должно вырасти. Числа — из кода; если код и документ расходятся, прав код, документ надо поправить.

## 1. Архитектура: три изолированных слоя

```
┌──────────┐   байты    ┌──────────┐   байты    ┌──────────┐
│   МИР    │ ─────────► │  КАНАЛ   │ ─────────► │ КОНСОЛЬ  │
│ world.js │ ◄───────── │ link.js  │ ◄───────── │console.js│
│ (Worker) │  команды   │          │  команды   │          │
└──────────┘            └──────────┘            └──────────┘
      │ физика линии (расстояние, препятствия, мощность) ─► канал
      │ несущая есть/нет по каждому миссионеру           ◄─ канал
```

- **Мир** — симуляция в Web Worker. Не знает о консоли. Наружу отдаёт только байтовые сообщения `{id, cls, kind, unit, payload}` и физическую правду о линии (расстояние миссионера от станции, затухание в препятствиях, мощность его передатчика).
- **Канал** — единственный путь из мира в консоль. Очередь, ёмкость, потери, планировщик. Обратный путь (команды) тоже через него.
- **Консоль** — видит только сообщения станции: доставленные пакеты, потери и показания своего модема. Всё на экране восстановлено из этих пакетов. Отладочная шторка показывает правду о мире, если станция её отдаёт (только в одиночной игре), и помечена как «игрок этого не видит».

Честность — свойство архитектуры, а не дисциплины: консоль физически не может показать то, что не пришло.

**Станция** (`station.js`) — мир + каналы в одном хосте, наружу только сообщения. Хоста два, консоль разницы не видит:
- `station-worker.js` — Web Worker, одиночная игра и лаборатория: грузит текст мира по сети и гонит такты сам, платформа одна;
- `server/index.js` — Node на сервере, сетевая игра (`index.html?room=КОД&st=k`): комната = один мир с 2…4 посадочными платформами (ARK-041…044, число — настройка комнаты, не больше слотов в уровне), оператор при входе выбирает платформу; WebSocket `/ws?room=`. Раздаёт `proto/` статикой (кроме редактора), мир идёт только пока в комнате есть операторы.

**Платформы.** Мир один, платформ в нём `NST` (хост передаёт `&st=N` в `search` мира; уровень хранит слоты `LEVEL.stations`, поднимаются первые N). У платформы своё: миссионеры (`u.st`), биоматериал, склад, выращивание, задача, пульс, стационарная камера и **свой канал 512 бит/с** — свой `Link` с очередью, планировщиком, ARQ и модемом. Общее: рельеф, ориентиры, предметы, одичалые, мачта с усилителем (включённый усилитель поднимает линии всех платформ — это физика мачты). Каждое сообщение мира адресовано платформе (`st`): станция кладёт его в канал этой платформы, сервер отдаёт только её операторам. Команды приходят с `st` канала, по которому пришли; чужим телом платформа не управляет. Несколько операторов на одной платформе — кооператив: канал делят, миссионеры и журнал общие. Тела другой платформы в описании — `миссионер М3, ARK-042`, её шлюз — `шлюз ARK-042`; мёртвое чужое тело — контейнер, как своё. Возврат по ПС-2 — от своей платформы и мачты.

Мир в обоих хостах грузится одним способом — текстом через `new Function` с шимами воркера (`self`, `importScripts`, `postMessage`, таймеры), как в headless-проверках `tools/`; `world.js` о хосте не знает.

Сообщения консоль ↔ станция:
- вниз: `{t:'pkt', n, at, msgId, kind, unit, seq, total, bytes, size, latency}` — доставленный пакет, `n` — сквозной номер доставки (по нему сервер досылает пропущенное), `at` — время станции; `{t:'drop', …, reason}`; `{t:'modem', at, speed, up, cap, orbit, qbg, qcmd, ncmd, retry, sec, cnt, queue[]}` — раз в секунду игрового времени, показания модема оператора (ёмкость, очереди станции, ETA запросов, статистика секунды для графика «Канал»); при отладке — ещё `dbg` (положения тел, одичалые с действием и страхом, крики последних секунд, физика линии по телам, конфиг канала);
- вверх: `{t:'up', bytes}` — байты команды (§4); `{t:'speed', v}` — все с `st` (в воркере 0, на сервере — платформа оператора, клиентское значение не учитывается); сетевой хост — ещё `{t:'hello', since, st, op}` при (пере)подключении, ответ `{t:'welcome', st, name, operators, replay, at, speed}` и досылка пакетов с `n > since` (помечены `replay:true`); только при отладке — `{t:'cfg', k, v}`, `{t:'tp'}`, `{t:'peek'}`. `load`/`save` в сетевом хосте от клиентов не принимаются: мир — у сервера.

Показания модема — не игровые пакеты, а то, что терминал оператора знает о собственной линии; по каналу они не идут и байт не стоят. Часы консоли идут за станцией: поправка из `modem.at`.

**Идентификаторы объектов** (один байт в пакетах): 2…9 — ориентиры уровня (id = тип), 10…99 — их подобъекты (id·10 + индекс), 100…159 — свёртки на грунте, 160…199 — подобъекты шлюзов платформ (160 + k·4 + i, до 4 на платформу), 200…239 — миссионеры (200 + номер, номера сквозные по всем платформам), 240…249 — шлюзы платформ (240 + k, класс «ориентир», тип 1), 250…259 — одичалые (250 + номер особи в уровне, класс 2, тип 250). Положение своей платформы консоль узнаёт из паспорта (`INFO`, строка `платформа: x, y; курс d°`) — по нему рисуются корпус и круг возврата.

**Лобби** — `lobby.html`, корень сервера (`/`): имя оператора (хранится в браузере как `missioners.op = {name, token}`, токен случайный — им сервер узнаёт оператора), список станций (`GET /rooms`: код, операторы онлайн, часы мира, живые миссионеры, последняя связь; живые комнаты — из памяти, остальные — по файлам в `DATA_DIR`), вход по коду — код и есть ключ доступа. Имя и токен уходят в `hello {op}`; сервер шлёт всем в комнате `{t:'ops', ops:[имена]}` при входе и выходе — консоль показывает их в шапке (`#room`) и пишет в лог с пометкой «терминал:» (это знание инструментария, не станции). На GitHub Pages лобби нет: без сервера оно бессмысленно.

## 2. Канал: два плеча

**Плечо 1, локальное** — радио миссионер ↔ станция. Физика по каждому миссионеру.

```
FSPL(d)  = 20·log10(d) + 20·log10(f_МГц) − 27,55         f = 430 МГц
SNR      = P_tx + G_мис + G_ст + G_доп − FSPL − L_преп − N
           P_tx  = −10…+10 дБм (регулируется, ест заряд)
           G_мис = −5 дБи (имплантированная антенна), G_ст = +6 дБи
           G_доп = +6 дБ после включения усилителя ретранслятора
           L_преп: расщелина — 8 дБ у входа + 22 дБ·глубина (доля пути вдоль дна; стены перекрывают прямую видимость)
           N     = −92 дБм (тепловой −130 + NF + помехи от реактора)
C_лок    = B · log2(1 + SNR_lin) · 0,5 · (FEC ? 0,5 : 1)   B = 4 кГц
           ниже SNR = −5 дБ несущая не захватывается: C = 0
BER      = 0,5 · erfc(√SNR_lin)   с FEC: SNR + 5 дБ
PER(n Б) = 1 − (1 − BER)^(8n)
```

Каждое удвоение расстояния — −6 дБ. Ориентиры: у шлюза SNR ≈ 44 дБ; вход в расщелину ≈ 10 дБ; середина ≈ 4 дБ (без FEC пакеты бьются на 90 %, с FEC — проходят); глубина ≈ −11 дБ — связи нет.

**Плечо 2, дальнее (СВС)** — станция ↔ оператор. Расстояние не влияет, ёмкость фиксированная: **512 бит/с** (ползунок 64…16000 в отладке). Битовые ошибки 1e-7. Опционально окно видимости ретранслятора (для варианта без СВС) — по умолчанию выключено.

Пакет считается доставленным, когда прошёл оба плеча: у станции буфер (store-and-forward). Потери считаются по локальному плечу для пакетов миссионеров и по дальнему для пакетов станции.

## 3. Пакеты и планировщик

```
заголовок 8 Б: msgId(2) kind(1) unit(1) seq(2) total(2)
полезная нагрузка ≤ 64 Б
```

Классы:
- **bg** (подписки) — очередь по ключу `unit:kind`, хранит одно сообщение: свежее вытесняет недоставленное старое. Исключение — кадры (`IMG*`, `IMD*`): пока предыдущий кадр не ушёл целиком, новый не принимается («кадр пропущен: предыдущий ещё передаётся»), иначе дельты теряют опору.
- **cmd** (ответы на команды) — FIFO. Потерянные пакеты повторяются через RTT (ARQ, до 6 раз). Пакеты миссионера вне зоны пропускаются (нет head-of-line blocking по нему), остальное — строго по порядку.

Такт 100 мс. Подписки идут раньше команд, но не больше 40 % полосы в секунду — команды не голодают. Среди подписок пульс станции всегда первый, остальные — по кругу (round-robin по ключам), и планировщик ждёт бюджета на пакет во главе очереди, а не обгоняет его мелкими: иначе при пяти телах с секундной телеметрией (120 Б/с при ёмкости 64) пульс станции не получал слота никогда. Бюджеты — token bucket: дальний и по одному на миссионера; ведро не копит ёмкость, пока канал молчит (max 0,3 с), но вмещает минимум два пакета — иначе большой пакет на слабой линии не уйдёт никогда (реальный баг, найден в прототипе). Порядок в такте: подписки → команды.

Вверх (консоль → мир): команды 3…7 байт, задержка RTT/2 = 0,3 с, требуют живого дальнего плеча. Направления независимы (как две линии, а не одна общая полоса): полоса вверх не моделируется — команды ничтожны, вниз идёт всё остальное. Забитая очередь вниз не мешает отправить команду; она задерживает только *ответ*. Индикатор занятости — лампа у вкладки «Канал»: зелёная — очередь пуста, жёлтая — есть, красная — больше 10 с ожидания.

## 4. Протокол вверх (команды)

| код | байты | смысл |
|---|---|---|
| 1 | `[1,0,unit]` | описание (нужно живое тело) |
| 2 | `[2,tilt+90,unit]` | лидар; наклон лучей −45…+45° к горизонту (0 во втором байте — горизонт, старый формат). Наклон запоминается и используется автосъёмкой |
| 3 | `[3,level,unit,delta]` | кадр: уровень 0…3, дельта 0/1. `unit=0` — камера шлюза (стационарная, у станции) |
| 6 | `[6,0,unit,xh,xl,yh,yl]` | идти в точку; тело идёт и смотрит туда. Цель дальше радиуса возврата (§6, «Граница») станция не принимает — событие 28 |
| 7 | `[7,mode,unit]` | режим — команда: 1 исследование, 3 отступление (бегом к шлюзу), 4 отдых. 2 и 5 больше не принимаются: скрытность — команда 24, бой — стойка 25 |
| 8 | `[8,objId,unit]` | взаимодействовать: подойти и выполнить действие для текущего состояния объекта |
| 9 | `[9,dBm+20,unit]` | мощность передатчика (−10 / 0 / +10 дБм; в игровом интерфейсе — в панели тела) |
| 10 | `[10,mask,0]` | вырастить: bit0 камера, bit1 лидар |
| 11 | `[11,0,0]` | статус станции: паспорт текстом (`INFO`) + пульс. Этим же начинается сеанс |
| 12–14 | `[k,interval,unit]` | подписки: телеметрия / лидар / описание, 0 = выкл |
| 15 | `[15,interval,0]` | пульс станции |
| 16 | `[16,interval,unit,level,delta]` | автосъёмка; `unit=0` — камера шлюза |
| 17 | `[17,0,unit]` | стоп (цель остаётся) |
| 18 | `[18,0,unit,xh,xl,yh,yl]` | смотреть: повернуть голову к точке, не идя |
| 19 | `[19,objId,unit]` | изучить: подойти и доложить состояние объекта |
| 20 | `[20,itemId,unit]` | использовать предмет: 40 брикет → глюкоза +50, электролиты +20 |
| 21 | `[21,itemId,unit,dir]` | обмен со складом у шлюза (в 12 м от люка): dir 0 — сдать, 1 — взять; 42 — камера (датчик) |
| 22 | `[22,itemId,unit,objId]` | положить предмет в контейнер (подойти и сделать); objId 0 — сбросить на грунт: возникает «свёрток» (id 100–199) |
| 23 | `[23,itemId,unit,objId]` | взять предмет из контейнера |
| 24 | `[24,on,unit]` | скрытность — настройка тела: без фонаря, 0,6 м/с, шум шагов ниже; не действует, пока идёт рефлекс по стойке |
| 25 | `[25,stance,unit]` | стойка при контакте — настройка тела: 0 пассивно, 1 бегство, 2 бой (§6 «Стойка») |
| 26 | `[26,v,unit]` | инструкция на потерю несущей — настройка тела: 0 продолжать, 1 стоп, 2 к шлюзу. Срабатывает после 5 с без несущей (`LINK_LOST_S`). Раньше шла мимо канала сообщением транспорта |
| 27 | `[27,0,unit,idHi,idLo]` | отменить запрос: буфер станции выбрасывает все ещё не переданные пакеты сообщения `msgId` (и его повторы ARQ). До мира команда не доходит — это операция канала; ушедшие байты не возвращаются. Если отменён кадр, мир сбрасывает базу дельты — следующий кадр этого уровня ключевой. Номер сообщения консоль берёт из показаний модема (очередь). Кнопка «✕» — только в таблице очереди вкладки «Канал»: отмена — операция с буфером, а не с панелью |

Координаты — дециметры, смещение +32768, big-endian (16 бит: ±3276 м, шаг 0,1 м); в пакетах вниз координата за пределом обрезается по краю, не заворачивается.

## 5. Протокол вниз (виды сообщений)

| kind | класс | размер | содержимое |
|---|---|---|---|
| `TLM` | bg | 16 Б | пульс, электролиты, глюкоза, токсины, кожа, кости, психика, опасность, потребление, заряд, генерация, x(2), y(2), байт 15 = режим (биты 0–2) \| скрытность (8) \| стойка (16, 32) \| рефлекс (64 бой, 128 бегство); байт 7 = опасность (бит 0) \| инструкция на потерю несущей (биты 1–2) |
| `HB` | bg | 6 + 5n Б | пульс своей платформы: биозапас, камеры на складе, рост (с или 255), брикетов на складе, резаков на складе, n — только её тела; по миссионеру: id, флаги (жив, несущая, камера, лидар, автосъёмка, у шлюза), заряд, предметы (биты 0–1 — число брикетов, бит 2 — резак), SNR+30 дБ — станция измеряет уровень сигнала каждого тела; без заряда передатчик молчит, несущей нет |
| `DESC` | cmd/bg | 4 + (5 + имя) Б × объект | x, y съёмки (2×16 бит); далее по объекту: id, класс (0 объект, 1 ориентир, 2 неопознанное, 3 тело, 4 миссионер), пеленг/2, дальность (м, ≤255), длина, имя текстом |
| `SONAR` | cmd/bg | 79 Б | x, y съёмки; наклон+90; высота датчика над уровнем станции (2 Б, (z+40)·10, шаг 0,1 м — барометр тела; шаг 0,5 м давал ступеньки между снимками выше сечения изогипс); маска «сплошное» 64 бита — поверхность вдоль луча круче 40° (`MAX_SLOPE`: корпус, обломки, стены расщелины, обрыв), измеряется на теле парой лучей; 64 луча, наклонная дальность/100 м × 255. Консоль проецирует на горизонталь по наклону. Координаты в пакете нужны, потому что к моменту доставки тело уже ушло на несколько метров |
| `IMG0…3` | cmd/bg | 64 / 256 / 1024 / 4096 Б | уровни пирамиды 8×8 → 64×64, 8 бит серого; запрос уровня k шлёт уровни 0…k |
| `IMD0…3` | cmd/bg | 2 + Σ(1 + (side/8)²) | дельта-кадр: `[frameNo, key, (idx, блок)*]`, сетка 8×8 блоков, уходят изменившиеся (порог 18) |
| `EVT` | cmd | 2 Б | код события, аргумент. 28 — отказ по ПС-2 (цель дальше радиуса возврата), аргумент — расстояние до ближайшего узла в десятках метров (≤255). 29–35 — стойка: тело приняло бой / бежит к узлу / контакт окончен, продолжает задачу / скрытность (аргумент 0/1) / стойка задана (аргумент) / бегство окончено, стоит / инструкция на потерю несущей задана (аргумент) |
| `INFO` | cmd | текст | паспорт станции: блок (`ARK-04k`), состояние, возраст миссии, оператор, положение платформы («платформа: 180, −150; курс 0°» — по нему консоль рисует корпус и круг возврата), запасы, радиус возврата и число узлов («возврат: ПС-2, 500 м от узла; узлов 1»), задача. Всё — про свою платформу |
| `CONT` | cmd | 2 + n Б | содержимое контейнера: id, n, предметы. Досылается после осмотра, вскрытия, положить/взять |
| `EXAM` | cmd | 4 + текст | id, 0, длина (2 Б), текст осмотра — составлен станцией из состояния мира |
| `ACT` | cmd | 4 + текст | id, код результата (0 сделано, 1 нечего делать, 2 нужен предмет, 3 условие не выполнено), длина (2 Б), текст |

Размеры с заголовками: телеметрия 24 Б, лидар 87 Б, описание 14 объектов ≈ 230 Б, осмотр ≈ 40–80 Б, кадр 32×32 пирамидой 1376 Б, 64×64 — 5536 Б, ключевой дельта-кадр 32×32 — 1234 Б.

**Текст по каналу.** Описания, осмотры и результаты действий — текст, составленный станцией из её базы знаний и текущего состояния мира (`nameOf`, `examText` в `world.js`): «тело М1», «существо, класс не определён» / «объект, класс не определён» (спит), «Не двигается. Камеры нет. При нём: резак». Ничего не перечислено заранее на стороне консоли. Кодировка однобайтовая, в духе КОИ-8 (`encText`/`decText` в `codebook.js`): кириллица, латиница, цифры, знаки — байт на символ. Многопакетные сообщения консоль собирает по `msgId` (`assemble`). Коды остаются только у системных событий (`EVT`), режимов и предметов — это протокол, а не мир.

**База знаний станции** (`codebook.js`) живёт в мире: логика состояний и шаблоны текста. Консоль берёт из файла только кодек текста, коды событий, режимов и предметов. Типы 1…7 — ориентиры, 10…33 — объекты (32 планшет, 33 свёрток), 250 — неизвестный, 251 — тело миссионера, 252 — живой миссионер. У типа: `states[]` — текст по состояниям (ответ на «изучить»), `actions[]` — `{from, to, verb, item?, needs?, req?, fail?, special?}`: переход состояния, глагол для журнала, выдаваемый предмет, требуемый предмет, требуемое состояние другого объекта, текст отказа. Предметы: 40 брикет, 41 резак, 42 камера (становится датчиком). Пример зависимости: резак (у входа в тоннель) → срастить кабель у мачты → включить усилитель (+6 дБ).

**Контейнеры.** Тип с полем `container: k` — контейнер, содержимое видно и доступно с состояния k (ящик — после вскрытия, груда — после разбора, камень с резаком, свёрток, тело — всегда). Мир хранит `contents[id]`; у тела содержимое — его предметы плюс камера (42). Передача между миссионерами — только через контейнеры (положить + взять), прямой передачи нет.

**Описание издалека** отдаёт только тип; подробности и изменения — через «изучить»/«взаимодействовать», которые требуют подойти (тело идёт к объекту, по прибытии выполняет — `pending`). Мир хранит `objState[id]`; консоль ведёт **журнал** по объектам — текст станции как есть: «М1 · ящик: Запечатан. Пломба цела.», «М1 · ящик: вскрыл. Вскрыт. Здесь: пищевой брикет.»

## 6. Мир

- **Уровень** (`level.js`, объект `LEVEL`) — данные первого акта, отдельно от логики: посадочные платформы (`stations`: центр корпуса и курс, шлюз с подобъектами, точка старта), ориентиры с подобъектами (тип, смещение, курс в градусах, начальное состояние, содержимое контейнера), колена и ширины расщелины, корпуса кроме платформы, стая одичалых (логово и особи с лёжкой и чертами), сюжетные декорации. `world.js` строит из него `POIS`, `HULLS`, `objState`, `contents`, `pack`; `terrain.js` — расщелину, хребет и `FIXED`; производные пересчитывает `TER.reload()`. Правила видимости ориентиров по расщелине — из геометрии (`TER.inside`, `tunnelT`), а не по id. Файл пишет редактор (§11); комментарии-имена в нём восстанавливаются из кодовой книги. Свойства типов (спрайт, высота отражателя, радиус для лидара) остаются в `codebook.js` и `world.js`.
- **Рельеф** (`terrain.js`, объект `TER`) — одно поле высот `H(x,y)` в метрах: равнина с дюнами по ветру, посадочное поле у ARK-041 (плоско, пусто; остальные платформы стоят на естественном рельефе — места выбраны по уклону, поле под них рельеф не делает), хребет с позвоночником в 28 м за входом в расщелину (гребень 26–35 м, со стороны станции обрыв в три террасы и осыпь, с другой — пологий склон), **расщелина** — ломаная из пяти колен с тупиковым отростком (`LEVEL.canyon`, ширина 9 → 4,5 м), вырезанная в хребте до уровня дна; в конце — завал. `tunnelT(x,y)` — доля пути вдоль дна (0…1) или −1 снаружи: от неё считаются затухание радио, токсины и темнота. Тона грунта и породы, органические маты в низинах, процедурные декали плоских объектов (следы, борозды, гарь, кабель, вода) — там же. Дизайн местности — `design.md` §11б.
- **Декорации** (`TER.decor`): валуны двух видов, россыпи, сухостой, скальные выходы у подножия, останцы на дальней равнине — по хешу координат; сюжетные — списком в `LEVEL.decor`: завал в конце расщелины, поле обломков вокруг корабля, семь пирамидок по тропе от ящиков ко входу, восемь столбиков кабеля от станции к мачте. В кадр и в лидар попадают (`DECOR_R`: радиус футпринта в долях `Hs`, высота `Hs`; сухостой не отражает, столбик кабеля — 8 см), в описание и на карту — нет.
- Ориентиры с подобъектами (смещения из уровня; курс подобъекта, если задан, выбирает ракурс спрайта и направление декали); глубина расщелины (ориентир 7) и её подобъекты — на дне последнего колена. Препятствия: корпус платформы (эллипс `STATION`) и круги из `LEVEL.hulls` (обломки, r 4).
- **Миссионер**: позиция, курс (направление последнего движения), цель `goal`, движение `target`, режим, тело (несколько ОДУ: пульс → 60 + 55·нагрузка + 95·страх + 45·боль; глюкоза (0,003/с в покое, ×3 на ходу: ~9 ч / ~3 ч), электролиты, токсины в расщелине, психика от страха и темноты; заряд = (генерация − потребление)·0,01/с: ходьба с фонарём ~3 ч, стоя почти ровно, отдых восстанавливает; при 0 — смерть, приборы на мёртвом теле молчат), датчики, подписки, `lastImg` по уровням для дельт.
- **Камера** (`camera.js`, объект `CAM`): `camHeading` = на цель, если она есть и не достигнута, иначе курс. Поле зрения 50°, высота глаз 1,6 м. Кадр — рэймарчинг по полю высот (нормали → солнце снаружи, фонарь в расщелине, без фонаря — только ближний метр; дымка по расстоянию, дальние планы на небе), объекты и декорации — спрайты-билборды из атласа `sprites.png` (таблица `SPRITES` в `codebook.js`: лист из 5 ракурсов + зеркало, реальная высота в метрах; курс объекта выбирает ракурс; состояние подменяет лист: существо спит/стоит, миссионер стоит/идёт/тело), тени — контактная и от солнца — и декали по точкам земли. Рендер в удвоенном разрешении с усреднением, спрайты усредняются по футпринту пикселя. Пирамида и дельты рендерят кадр нужного размера (32×32 — ~60 мс, 64×64 — ~350 мс в воркере). Атлас собирается `tools/sprites-build.js` из raw-листов (в репозиторий не входят; id ассетов — `tools/spritecook-assets.json`); до загрузки атласа объекты — серые блоки. `renderRaw(u,W,objs,{H,fov,heading,z})` умеет кадр W×H с другим полем зрения, курсом и высотой глаз — для `tools/banner.js` (шапка лендинга, FOV 75, 480×120 ×3) и свободной камеры редактора; игра рендерит квадрат.
- **Режим, скрытность, стойка, рефлекс** (`world.js`, перед стаей). Режим `mode` — команда 7: исследование 1,4 м/с, отступление 2,6 м/с к точке старта, отдых стоя (психика +, заряд +). Скрытность `stealth` — настройка (команда 24): фонарь выключен, 0,6 м/с (в отступлении тоже: «тихо» важнее), шум шагов ∝ v² — слышно с ~4 м вместо ~24, одичалые видят с 6 м вместо 70. Стойка `stance` — настройка (команда 25); рефлекс `reflex` — что тело делает по ней сейчас; пока он идёт, `lightOn = !(stealth && !reflex)` включает свет, после — снова гасит. Инструкция на потерю несущей `autonomy` — настройка (команда 26), в байте 7. Всё это консоль показывает только из телеметрии: кнопка с контуром — запрошено, залитая — подтверждено; запрос, который телеметрия не подтвердила за 90 с, снимается. Старые сохранения: режим 2 → скрытность, 5 → стойка «бой».
- **Стойка при контакте** (`stanceTick`, `contact`): рефлекс тела на одичалого — канал для реакции слишком медленный (инструкция на потерю связи — тот же принцип). Контакт — глазами тела, без стены (`losFrac` < 0,34), или укус за последние 3 с. *Бегство* (стойка 1): любая бодрствующая особь в 15 м при фонаре (4 без) — тело бежит 2,6 м/с к ближайшему узлу (точка старта своей платформы, мачта с усилителем) по точкам: в расщелине и на подходе — вдоль оси наружу, снаружи — прямо к узлу; чужих не видно 20 с или узел в 3 м — стоит, событие 34; «стоп» тоже снимает бегство. *Бой* (стойка 2): угроза — особь, идущая на тело или нападающая, в 8 м, либо любая в 3 м (смотрящая с 12 м — не повод); тело останавливается, цель запоминает, бьёт ближайшую особь в 4 м раз в 2 с (`fightBack`); 10 с без угрозы — возвращает цель и идёт дальше, событие 31. Пассивно (0) — как раньше: тело ничего не делает. Прогон — `tools/pack-check.js [шаг] [стойка]`.
- **Столкновения**: тело (радиус 0,6 м) не идёт на склон круче 40° (`MAX_SLOPE`, tg = 0,84: стены расщелины, обрыв — нет; дюны, осыпь, завал — да) и не проходит сквозь корпус платформы и обломки; цель внутри корпуса (ориентиры «обломки», «шлюз» и их подобъекты стоят в центре) переносится на ближайшую точку снаружи со стороны тела, а не отвергается; при упоре шаг поворачивается на ±45°/±90° (скольжение); если за 4 с не приблизилось к цели на метр — стоп и событие «путь перекрыт». Поиска пути нет: расщелина проходится точками по коленам. Одичалые ходят с теми же столкновениями; в расщелине идут по её оси (`packStep`): к цели в другом колене — сначала вдоль оси до её отметки, снаружи — сначала ко входу.
- **Лидар** (в коде и протоколе — `sonar`/`SONAR`, историческое имя): 64 луча с высоты `SONAR_H` = 1,7 м над грунтом (голова; глаза камеры — 1,6) под наклоном `u.sonarTilt`; луч (`castRay`) идёт по полю высот шагом 0,5 м с уточнением бисекцией, дальность наклонная. Бит «сплошное» — измерение, не подсказка мира: на каждый азимут второй луч на `SONAR_DT` = 3° выше, обе точки попадания лежат на поверхности, крутизна хорды между ними — уклон поверхности вдоль луча; хорда круче `MAX_SLOPE` (40°, куда тело не пройдёт) — «сплошное». Вертикальная стена вертикальна с любого азимута; склон, взятый наискось, кажется положе; объект, над которым второй луч прошёл, — не сплошной; второй луч без эха — не сплошное. Корпуса (`HULLS`: платформа — эллипс `STATION` из кодовой книги 16×9 м, обломки — круг) и объёмные объекты — по высоте отражателя (`OBJ_H`): луч выше объекта проходит. Наклон вниз даёт эхо от грунта на каждом луче — профиль рельефа; в панели грунтовые цепочки — тусклые линии, сплошные — яркие. Снимки из соседних точек ложатся на одну линию — расхождение в пределах шага квантования дальности (0,4 м).
- **Одичалые** (`design.md` §12а; в `world.js` — блок «одичалые»): стая `pack` из особей уровня (сейчас пять в двух последних коленах расщелины, логово — конец расщелины за завалом, (341,5; 219,5)). Особь: черты `size`, `courage`, `attention` (0…1), состояние `hp` (= 3·size), `fear`, `tired`, `act` (sleep / idle / freeze / approach / attack / back / flee / home / rest / goto), `foe` — чужой, которого видела или слышала недавно (окно 20 с + 60·(1 − courage): пугливые долго не выходят). Мир не знает, кто за них играет: намерения агента (потом) лягут в ту же `target`, рефлексы останутся.
  - *Действующая храбрость* `nerve = courage + 0,15·(size−1) − 0,6·fear − 0,5·(1 − hp/hpMax) − 0,3·max(0, (расстояние до логова − 120)/150)`: страх, раны и удалённость от дома отнимают, размер добавляет. Дальше 270 м от логова храбрый перестаёт нападать, дальше 420 — бежит домой: поводок без правила.
  - *Чувства* раз в 0,5 с (сдвиг по особям): зрение — `detectRadius(тело)` (70 м с фонарём, 35 в отдыхе, 6 без фонаря — скрытность или рефлекс её не снял) × k, слух шагов — `min(80, 12·v²)` × k (v — скорость тела, м/с: крадущегося слышно с ~4 м, идущего с ~24, бегущего с 80); k = 0,2 + 0,3·attention во сне, 0,6 + 0,8·attention бодрствуя, ×1,4 настороже (20 с после крика). Стены — `losFrac(a,b)`: доля отрезка на высоте 1,2 м, закрытая рельефом или корпусом; зрение требует < 0,34, слух гасится на 75 % доли. Заметила чужого впервые — кричит: `nerve < 0,35` — «тревога», иначе «чужой» с вероятностью 0,25 + 0,7·attention.
  - *Рефлексы* по `nerve` и расстоянию d до чужого: < 0,3 — бежит в логово (2 м/с), у логова ложится на 90…180 с (`rest`, случайно — стая не ходит по часам), раненая кричит «домой»; 0,3…0,6 — при d < 12 отходит на 10 м по оси расщелины прочь от чужого (`backOff`; в тупике отходить некуда — стоит), иначе замирает и смотрит; ≥ 0,6 — подходит на 8 м и смотрит, нападает при `nerve ≥ 0,8`, вплотную (d < 2,5) или по слову «бей»; начатую драку бросает при `nerve < 0,5`, не < 0,6. Устала (`tired > 0,8`, ~2 мин погони) — передышка. Без чужого возвращается на лёжку, через 90 с засыпает. Раны затягиваются: +1 за 40 с у логова, за 120 с в покое.
  - *Удар*: вплотную (2,2 м) каждые 2 с — кожа −10·size, кости −4·size, боль, психика −6, событие 4. *Отпор*: тело в рефлексе «бой» (стойка 2) бьёт ближайшую особь в 4 м каждые 2 с: hp −1, страх +0,35·(1,2 − courage); на нуле особь бежит в логово, событие 9 один раз.
  - *Крик* (`cry`): слово из шести (тревога, чужой, сюда, бей, домой, добыча), кулдаун глотки 6 с, радиус 120·(0,8 + 0,4·size) м с тем же `losFrac` (−70 % за стеной), слышимость `loud` = (1 − d/R)·(1 − 0,7·доля). Реакция по `nerve` слушающей — таблица в `design.md` §12а; на «чужой» идут к крикнувшему (`goto`), не к чужому — крик несёт направление источника; реакция держится `hold` = 15 с, пока особь сама не увидит чужого или не дойдёт (иначе `decide` без своего чужого отменял её через полсекунды — так и было, лог мира показал); пугливая с вероятностью 0,5 повторяет «тревогу» (не чаще раза в 15 с) — так весть идёт дальше одной глотки. Любой крик громче 0,25 будит. Тела в радиусе получают `startle` (+0,6·loud, спад 0,1/с) → страх → пульс; слов не разбирают.
  - *Для оператора*: бит 7 телеметрии — бодрствующая особь в 90 м; страх тела — max по особям (1 − d/80) с весом 1 для нападающей и подходящей, 0,5 для прочих бодрствующих, 0 для спящих и уходящих, плюс `startle`. В описании — «объект, класс не определён» (спит / лежит) или «существо, класс не определён», осмотр называет размер (крупное / мелкое) и что делает (уходит, идёт сюда, смотрит); лидар — отражатель 0,5·size м высотой 1,6·size (0,6 лёжа); в кадре — тот же лист, высота по размеру, идущая особь — по курсу. `LAB` — стая спит.
- **Мёртвое тело**: остаётся, приборы работают на остатке заряда (утечка 0,004/с, 0,03/с при автосъёмке). Появляется в описаниях других как тип 251.
- **Взаимодействие**: шкаф усилителя (id 31) — +6 дБ ко всем линиям (требует срощенного кабеля, id 32, для которого нужен резак); обмен со складом — из консоли станции у шлюза (12 м); камера с тела — «взять» как из контейнера.
- **Граница мира** — не физика линии и не рельеф, а протокол станции ПС-2: цель (команды «идти», «изучить», «взаимодействовать», «положить», «взять») дальше `RETURN_R` = 500 м от ближайшего **узла** станция не принимает — событие 28 с расстоянием до узла; тело и голова остаются как были. Узлы: центр станции (`STATION`) и мачта ретранслятора (ориентир 3) после включения усилителя (`antennaBoost`) — ретранслятор раздвигает границу, как и обещано дизайном. Бюджет линии (дБ) к границе не привязан: за границей несущая ещё может держаться, но станция не рискует биоматериалом. Рельеф и координаты за границей по-прежнему определены (функция от координат), поэтому это единственная стена.
- **Несущая**: канал каждый такт сообщает миру, кого из миссионеров станция слышит и с каким SNR; миссионер сам это знает (физика) и по инструкции (команда 26, в телеметрии байт 7) действует после 5 с тишины — секундный провал за камнем не считается. Команды телу без несущей не доставляются (событие 25); мёртвому доступны только приборы (24); без заряда приборы молчат (26).
- Время: такт 0,1 с; ускорение ×1/×2/×4 применяется к миру и каналу одновременно.

## 7. Изображения: подтверждение кадра

Дельта-кадр опирается на последний кадр, который *реально ушёл*. Мир не знает состояния канала, поэтому:

1. мир рендерит кадр, кладёт его в `pendingImg`, шлёт `IMD`;
2. канал либо принимает (нет незавершённого кадра того же миссионера) и отвечает `imgAck ok=true`, либо отбрасывает и отвечает `ok=false`;
3. мир обновляет `lastImg` только при `ok=true`.

Для кадров по кнопке (класс cmd) очередь принимает всегда, `lastImg` обновляется сразу.

Консоль собирает кадр по пакетам; сборка живёт, пока приходят пакеты (90 с без пакетов — сброс). Блок, попавший на границу потерянного пакета, не применяется. Новая пирамида чистит холст, чтобы был виден прогресс; дельта — нет.

## 8. Консоль

**Эхо сокомандника.** Кто отправил команду — знание земной стороны: аплинк рождается в терминальной комнате, и сервер отдаёт остальным консолям той же платформы `{t:'echo', st, op, bytes}` в момент приёма, до канала. Это не нарушает «всё прошло через канал» (команда ещё не на планете, знание о ней ничего с планеты не несёт) и не нарушает «связь только через планету» (то про разные платформы). Консоль пишет в журнал «Б → М1 при контакте: бой» и помечает кнопку контуром с подписью, кто запросил; состояние тела по-прежнему только из телеметрии. Три источника изменения на экране: запрос (свой или эхо), состояние (TLM), причина (EVT 29–34 — рефлекс тела).

- Состояние по миссионеру: телеметрия и история, трек, последний лидар, описание, кадр, подписки, цель, инструкция.
- **Лидар на карте**: снимок при приёме разбирается по координатам съёмки и наклону из пакета (дальности проецируются на горизонталь) и растеризуется в две сетки; сами снимки консоль не хранит — только последний на теле, для панели. **Стены** (`wmap`): сплошные отсчёты, соседние с разницей дальности < 0,5 м + 30 %, соединяются отрезком (та же поверхность), отрезок растеризуется в ячейки 0,5 м (шаг квантования дальности 0,4 м — мельче смысла нет), в ячейке — число попаданий. На карте ячейки светлые: одно попадание тускло, три и больше — ярко; при отдалении ячейка меньше пикселя — точка. Двадцать снимков одной стены дают одну линию, а не пучок; стена, снятая раз издалека, остаётся тусклой навсегда — данные были приняты. Выключатель «стены» под картой. **Карта высот**: из дальности, наклона и высоты датчика консоль считает высоту каждой точки попадания и копит её в сетке 2 м (среднее по ячейке, до 8 отсчётов веса). Сплошные отсчёты в карту высот не идут: точка на вертикальной поверхности — не высота грунта в этой XY (на одной XY все высоты от подошвы до гребня, и какая попадёт в пакет, зависит от наклона и дальности, а не от рельефа; раньше вдоль стены получалась ложная лесенка +0,5 м на каждые 6 м при +5°, и изогипсы этой лесенки шли поперёк стены). Несплошные попадания в объекты (ящик, тело) ложатся как грунт с высотой точки на объекте. Ячейки, через которые прошла стена (`hwall`, из сплошных пар каждого снимка), — граница: сглаживание через них не тянется (раньше высота дна уходила на 4 м под скалу), изогипсы в квадратах с такой ячейкой не строятся (иначе между ячейкой стены и гребнем ложилась пачка ложных изогипс). Ячейки 2 м — производная от растра стен 0,5 м. На карте — заливка тоном по высоте и изогипсы через 0,5 м по центрам ячеек (marching squares); отрезки собираются в цепочки, цепочки короче 4 отрезков не рисуются — на плоском их даёт ошибка измерения, а не рельеф. Точность проверяется `node tools/hmap-check.js` (маршрут станция → расщелина, все наклоны): ошибка ячейки 0,03 м (медиана), изогипса в 1 м от истинной того же уровня; увязка снимков по перекрытию проверялась и отвергнута — при барометре 0,1 м она только добавляет дрейф. Карта высот и растр стен — в сохранении (`hmap`, `walls`; старое сохранение со снимками `sonar` растеризуется при загрузке). Низкое эхо (объекты) — только в панели, жёлтыми точками. Место объекта — из пеленга (шаг 2°) и дальности (шаг 1 м) описания, ошибка растёт с дальностью, поэтому для неподвижных объектов остаётся оценка с самой близкой съёмки (`range` в `known`); существо — всегда свежая. Подписи не налезают друг на друга: предмет уступает ориентиру и сдвигается вниз с выноской. Ориентиры (класс 1) — ромб с ножкой и имя прописными: это место; предметы, тела, существо — точка и имя строчными. Знак станции — контур корпуса `STATION` из кодовой книги, тот же, от которого отражается лидар. **Радиус возврата** — пунктирные круги вокруг узлов: радиус — из паспорта станции (`INFO`, строка «возврат:»), станция — всегда, мачта — после события 3 (усилитель включён) и если её место известно из описаний (`known`, id 3). Под картой — выключатели заливки и изогипс и срок показа пройденного пути (1/5/20 мин, весь); это только отображение, данные не трогает. Наклоны в списке: +5, 0, −1, −2, −3, −6, −12° — дальность до ровного грунта с 1,7 м ≈ 97/49/32/16/8 м.
- **Карта** — из телеметрии (треки, до 600 точек, кнопка стирания) и описаний (объект = координаты съёмки из пакета + пеленг + дальность; `seenBy` — кто видел, изученный или тронутый объект тоже становится знакомым). Покрытие описаний — единая область, последний снимок ярче. Холст в половинном разрешении, растянут на 7 % вширь. Клик — выбор (локально); двойной клик по миссионеру в шапке — перелёт к нему.
- **Расход по панелям** — скользящее окно 5 с по доставленным байтам каждого вида. Оценка под кнопкой «снять» — из размеров в §5 и текущей ёмкости.
- Данные старше порога приглушаются (`.stale`): тело — 3 интервала телеметрии, лидар и описание — 120 с, кадр — 300 с.
- Никакой логики мира в консоли нет; всё, что похоже на «знание», — кэш принятых пакетов.

## 9. Сохранение

`localStorage['missioners.save'] = {v, savedAt, world, console}` каждые 10 с (после открытия консоли) и при экспорте. `v` = `SAVE_VERSION`; при расхождении заставка предупреждает и советует новый сеанс.
- **Мир**: `snapshot()`/`restore()` в `world.js` — время, станция, состояния объектов, стая (`pack`, по индексу особи), миссионеры (без буферов кадров), усиление. `catchUp` есть, но при загрузке вызывается с 0: игровое время стоит, пока консоль закрыта; скрытая вкладка не пауза — мир в воркере продолжает идти.
- **Консоль**: `consoleSnapshot()`/`restoreConsole()` — время, активный, станция, счётчики, миссионеры (история до 600 точек, без буферов кадров), `known`, `journal`, содержимое контейнеров, карта высот и растр стен, лог (400 строк).
- Управление сеансом — в терминале заставки, одной клавишей: `[r/enter] resume [n] new [i] import file [e] export file`; «new» переспрашивает `overwrite stored session? [y/n]`; Enter — первый вариант. Экспорт — тот же JSON файлом; импорт — записать в хранилище и продолжить. В консоли кнопок нет.
- После восстановления заставка всё равно проходит через реальный запрос статуса; очереди канала перед восстановлением сбрасываются (`link.reset()` в станции).

**Сетевая игра** (`?room=КОД&st=k`): мир хранит сервер — JSON на комнату в `DATA_DIR` (App Service: `/home/data`, иначе `./data`): `{v:2, savedAt, world, n[], speed, seen, rings[][]}` — снимок мира, номера последних доставленных пакетов и хвосты доставленных пакетов (5000) по платформам, ускорение, операторы (токен → имя, платформа); запись атомарно через временный файл каждые 10 с, при уходе последнего оператора и по SIGTERM. Консоль хранит в браузере только своё знание (`missioners.save:КОД:k`, `world:null`) и `rxN`; при входе шлёт `hello {since:rxN, st:k, op}`, сервер досылает пакеты этой платформы с бо́льшим номером — журнал, карта и кадры восстанавливаются из тех же байт. Меню сеанса в сетевой игре нет: местное знание подхватывается само, новый сеанс — новая комната. **Настройки комнаты** задаёт создатель в лобби (`POST /rooms {code, n, cap, speed}`): число платформ (2…4), ёмкость дальней линии (512…4096 бит/с) и ускорение (×1…×4), одинаковы для всех платформ, потом не меняются, хранятся в `cfg` сохранения; при восстановлении число платформ берётся из файла — мир уже с ним. Лобби показывает состояние мира: «стоит · N назад» (операторов нет), «идёт · команды» (за последнюю минуту кто-то слал команды), «идёт · тишина». В сетевой игре **отладки нет**: кнопка шторки скрыта, селект ускорения заблокирован, сервер игнорирует `cfg`/`tp`/`peek`/`speed` от клиентов — мир общий, крутилки были бы читом. Локальный сервер с `debug` отдаёт правду о мире и принимает телепорт, как одиночная игра.

Отладка: `{t:'peek', unit}` → `{t:'peekImg', img}` — чистый рендер 64×64 мимо канала, только для шторки. `{t:'level', canyon, pois}` — мир шлёт один раз при старте: правда о мире для карты в шторке (расщелина, ориентиры); клик или перетаскивание по ней — телепорт (`{t:'tp'}`).

**Лаборатория лидара** — `index.html?lab`, только на localhost (на опубликованном сайте флаг игнорируется): та же консоль и тот же мир (`LAB` в `console.js` и `world.js`), но канал без ограничений (1e8 бит/с, шум −500 дБм, RTT 0, BER 0), заставка без меню сеанса, автосохранение выключено; клик по карте и стрелки (2 м, с Shift 10 м) — телепорт тела мимо канала с немедленным запросом лидара под выбранным наклоном; одичалые спят, тело не умирает. Панели кадра, описания и команды скрыты. Датчик, пакет `SONAR`, карта высот и изогипсы — игровые.

## 10. Куда расти

- **Настоящий кодек**: рендер → реальное сжатие → длина буфера = объём передачи. Тёмный кадр сожмётся лучше шумного. Прогрессивность через реальный progressive JPEG или вейвлеты.
- **Состояния в кадре**: вторые листы для вскрытого штабеля, раскопанной насыпи, шкафа с индикатором; особь «бьёт». Сейчас в кадре меняются только особь (спит/стоит) и миссионер (стоит/идёт/тело).
- **Декорации в столкновениях**: валуны и выходы породы видны в кадре и в лидаре (крупные — «сплошное»), но тело проходит сквозь них; для честности — круги-препятствия по `DECOR_R` в `stepBody`.
- **Зум**: угол обзора как параметр запроса кадра (40° по цели / 60° обзор) при том же размере в байтах.
- **Параметры запроса кадра**: разрешение × глубина × сжатие → ожидаемый размер → время.
- **Другие клиенты** (телефон, терминал) поверх того же протокола станции (§1) — сервер уже есть.
- **Синхронизация переключателей шапки** между консолями одной станции (чью подписку включил другой): HB несёт бит кадра, интервалы телеметрии/лидара/описания — дописать в пульс станции.
- **Кодовая книга как прогрессия**: новые типы появляются, когда игрок их «определил» картинкой.
- **Возвращение миссионера**: физический слив всего записанного при контакте со шлюзом.
- **Вычисления на станции**: запросы вида «сосчитать движущиеся объекты в кадре» → байты + уверенность.

## 11. Редактор уровня

`editor.html` + `editor.js` в `proto/` — инструмент, не игра: читает уровень, рельеф, камеру и физику линии напрямую, канала и воркера мира нет (правило «консоль не читает мир» на него не распространяется). Работает **только с localhost** (проверка `location.hostname` в загрузчике страницы; на опубликованном сайте — подсказка), запуск — `python3 proto/serve.py` → `http://localhost:8765/editor.html`.

- **Карта**: вид сверху, пан/зум; карта высот считается по сетке отсчётов текущего вида (`TER.H`, шаг 3 px, тон по высоте + светотень от `TER.SUN`), красным — склон круче `MAX_SLOPE` (тело не пройдёт), изогипсы marching squares с шагом по масштабу (0,5 / 1 / 2 / 5 м), пачки изогипс на стенах не рисуются. Слои: высоты, изогипсы, непроходимое, процедурные декорации (`TER.decor`), сетка, радиус возврата (пунктир вокруг станции и мачты при включённом усилителе), подписи.
- **Объекты**: ориентиры (ромб, ПРОПИСНЫЕ), подобъекты (точка, курс — штрих), колена расщелины и отростка (квадраты, ширина подписью), корпуса, платформы (эллипс с подписью `ARK-04k`; тянется вместе со шлюзом и точкой старта; шлюз — ромб «ШЛЮЗ», его подобъекты — как у ориентира, не больше 4), особи одичалых (черты в свойствах: размер, храбрость, внимательность) и логово, точки старта, сюжетные декорации (крестики). Перетаскивание двигает (ориентир — вместе с подобъектами; колено — с корнем отростка, если он на нём; ⇧ — шаг 1 м); клик — свойства: тип из кодовой книги, x/y и смещение, курс, начальное состояние, предметы, ширина колена, высота декорации. Добавление: подобъект (к выбранному или ближайшему ориентиру, не больше 10), ориентир (свободный тип 1…9), декорация, корпус, особь (не больше 10), колено (двойной клик по расщелине или «колено после»). Удаление — Del. Отмена — ⌘Z/Ctrl+Z (снимки `LEVEL` в памяти).
- **Курсор**: координаты, высота, уклон, положение в расщелине (метры от входа, ширина, глубина и затухание), расстояние от станции и до выбранного, SNR/ёмкость/потери для тела в точке при 0 и +10 дБм — тот же `Link` с расстоянием и затуханием, как их считает мир; выключатель усилителя. Линейка — режим R: отрезок с длиной, Δh и пеленгом.
- **Свободная камера**: кадр рендерит воркер (blob, `importScripts` level + codebook + terrain + camera, без `world.js`) тем же `CAM.renderRaw`; сцена — весь уровень без правил видимости (спящие особи на лёжках, платформа, фигура миссионера в точке старта для масштаба, декорации). Камера и цель — на карте, перетаскиваются; размер 128×80…256×160, поле зрения, высота глаз, фонарь; стрелки — полёт (вперёд/назад, поворот), PgUp/PgDn — высота; «кадр на выбранное» ставит камеру в 8 м от объекта. Автосъёмка после каждого изменения, запросы во время рендера сливаются в один.
- **Сохранение**: `POST /level.js` в `serve.py` — принимается только с loopback и только если тело начинается с заголовка уровня; пишется атомарно через временный файл. Если сервер не принял — текст файла показывается для копирования. Сериализация детерминированная: несохранённый уровень воспроизводится байт в байт. «Перечитать» — перезагрузка страницы; несохранённые правки — предупреждение при закрытии.

## 12. Лог мира

Полная запись сеанса для спектатора и разбора «что шло не так». Точка одна — `station.js`: через неё проходит всё, что входит в мир и выходит из него, и она общая для воркера и сервера. Хост даёт `opts.log(rec)`, станция добавляет `t` (часы канала = часы мира) и зовёт его; куда писать — дело хоста. Формат — JSONL, запись на строку, поле `k`:

| `k` | что | откуда |
|---|---|---|
| `start` / `restore` | начало лога (хост, число платформ, стенное время) / мир восстановлен из сохранения | хост / станция |
| `op` | оператор вошёл / вышел (имя, платформа, `since`) | сервер |
| `up` | байты аплинка как пришли по каналу (`st`, `bytes`) | станция |
| `pkt` | доставленный пакет: `st`, сквозной `n`, `kind`, `unit`, `id`, `seq/total`, байты `b` в base64 — то, что видел оператор | станция |
| `drop` | потеря с причиной | станция |
| `speed`, `cfg` | ускорение, отладочные крутилки канала | станция |
| `phys` | раз в секунду мира: тела `[id, st, x, y, alive]`, особи `[x, y, act, hp, fear]`, SNR по телам — правда о положениях для спектатора | станция из `dbg` мира |
| `note` | **заметка мира**: что решил и почему, `kind` + поля (ниже) | мир, `note()` в `world.js` |

**Заметки** — не трассировка, а решения с числами, от которых они зависели: ставятся там, где `if` с числами решает игровой исход и потом спросят «почему оно так». Сейчас: `cmd` — разобранная команда по имени (`идти`, `режим`, …) с платформой и телом; `pack` — особь заметила чужого (`sense`: see / hear, расстояние, режим тела, фонарь, nerve), сменила действие (`act`, `was`, `why` — «nerve 0,83, d 7,4» или «„тревога“ от #4, слышно 0,92»), укусила (`bite`, кожа/кости, режим тела), получила удар (`hitBy`, hp, страх); `cry` — кто, слово, откуда, кто слышал; `station` — отказ по ПС-2 с расстоянием до узла, серия закрыта; `unit` — смерть с причиной и жизненными показателями, несущая потеряна/восстановлена с SNR и местом, инструкция на потерю связи сработала, путь перекрыт с уклоном; `debug` — телепорт. Заметки идут **только в лог**: станция не пересылает `note` операторам ни в каком режиме — это правда о мире.

**Хосты.** Сервер — `data/КОД.log`, дописывается раз в `SAVE_EVERY` и при остановке мира. Воркер (одиночная игра) — память + IndexedDB (`missioners-log`, куски по 5 с; ключ `main` / `lab`); новый сеанс (`n` в заставке) очищает лог, возобновление продолжает; кнопка «лог мира» в шторке скачивает JSONL. Объём — около 1 МБ на час игры, основное — `phys` и `pkt`.

**Чтение.** `node tools/log-read.js data/КОД.log [stats | t0 t1]` — лента по игровому времени человеческим текстом (заметки, команды, вход/выход, потери) и сводка: пакеты по видам и Б/с, потери, команды, крики, смерти. Это первый слой разбора; разбор смыслом («оператор шёл в скрытности, но прошёл в 1,7 м от лёжки») — поверх этой ленты, скриптом или агентом, не в игре. Спектатор — воспроизведение `pkt`/`phys` в консоли с ползунком — не сделан (`roadmap.md`).
