# Миссионеры — техника: канал, протокол, мир

Контракты между модулями: что должно сходиться в `world.js`, `link.js`, `station.js`, `console.js`, `server/opconsole.js` и на сервере и чего не видно из одного файла. Числа — из кода; если код и документ расходятся, прав код, документ правится в том же коммите. Крутилки баланса (скорости, радиусы, формулы стаи и турели) живут константами с комментариями в `world.js` — здесь только механика и то, что уходит в канал.

Рядом: сервер и комнаты — `server.md`; инструменты (редактор, спектатор, лаборатория) — `tools.md`; как агенты входят в игру — `agent-api.md`; история изменений — `history.md`.

## 1. Архитектура: три изолированных слоя

```
┌──────────┐   байты    ┌──────────┐   байты    ┌──────────┐
│   МИР    │ ─────────► │  КАНАЛ   │ ─────────► │ КОНСОЛЬ  │
│ world.js │ ◄───────── │ link.js  │ ◄───────── │console.js│
│ (Worker) │  команды   │          │  команды   │          │
└──────────┘            └──────────┘            └──────────┘
      │ физика линии (расстояние, препятствия, мощность) ─► канал
      │ несущая есть/нет по каждому миссионеру           ◄─ канал
```

- **Мир** — симуляция в Web Worker, о консоли не знает. Наружу — только байтовые сообщения `{id, cls, kind, unit, payload}` и физическая правда о линии (расстояние тела до узла, затухание в препятствиях, мощность передатчика).
- **Канал** — единственный путь из мира в консоль и обратно: очередь, ёмкость, потери, планировщик.
- **Консоль** видит только сообщения станции: доставленные пакеты, потери и показания своего модема. Всё на экране восстановлено из пакетов. Отладочная шторка показывает правду о мире, если станция её отдаёт, с пометкой «игрок этого не видит».

Честность — свойство архитектуры: консоль физически не может показать то, что не пришло.

### Станция и хосты

**Станция** (`station.js`) — мир + по каналу на каждую платформу в одном хосте; наружу только сообщения с номером платформы `st`. Хоста два, консоль разницы не видит:

- `station-worker.js` — Web Worker: одиночная игра и лаборатория, платформа одна;
- `server/index.js` — Node: сетевые комнаты на 1…4 платформы (`server.md`).

Мир в обоих хостах грузится одинаково — текстом через `new Function` с шимами воркера (`self`, `importScripts`, `postMessage`, таймеры), как в headless-проверках `tools/`. Параметры мира — строка `search`: `?v=0&st=N[&teams=…][&voice=…]` (`worldSearch` на сервере). Мир не знает, кто играет.

### Платформы

- Мир один, платформ в нём `NST`. В уровне баз нет — только **площадки** `LEVEL.sites` (центр, курс, при желании сюжетные объекты у шлюза и своя турель) и **раскладка** `LEVEL.layouts[n]`: какие площадки заняты при n платформах и в каком порядке. Площадка 1 всегда ARK-041.
- Раскладка задаёт, на сколько платформ карта (`playersOf` в `codebook.js`, стая не в счёт): есть запись для n — играется на n. Без `layouts` — от 1 до числа площадок. Одиночная игра на карте без раскладки на одну отказывает сбоем воркера.
- База разворачивается, когда хост поднимает платформу: штатный состав `BASE` (`baseAt(site)` в `codebook.js`) — корпус `STATION`, шлюз в 10 м по курсу (там же точка старта), два запечатанных ящика (три брикета; две пачки патронов), турель в 6 м перед шлюзом. Смещения — в осях площадки. Люк и прожектор в кадре — часть спрайта платформы.
- **Своё у платформы**: миссионеры (`u.st`), биоматериал, склад, выращивание, задача, пульс, камера шлюза и **свой канал 512 бит/с** — отдельный `Link` с очередью, планировщиком, ARQ и модемом. **Общее**: рельеф, указатели, предметы, одичалые, ретрансляторы.
- Каждое сообщение мира адресовано платформе: станция кладёт его в её канал. Команда приходит с `st` своего канала; чужим телом платформа не управляет.
- Чужие в описании: `миссионер М3, ARK-042`, `шлюз ARK-042`; мёртвое чужое тело — контейнер, как своё.

### Сообщения консоль ↔ станция

Вниз:

| `t` | поля | что |
|---|---|---|
| `pkt` | `n, at, msgId, kind, unit, seq, total, bytes, size, latency` | доставленный пакет; `n` — сквозной номер доставки (по нему сервер досылает пропущенное), `at` — время станции |
| `drop` | …, `reason` | потеря |
| `modem` | `at, speed, up, cap, orbit, qbg, qcmd, ncmd, retry, sec, cnt, queue[], load[]` | раз в секунду игрового времени: показания модема (ёмкость, очереди, ETA запросов, статистика секунды; `load` — байты буфера по телу и виду `{unit, kind, bytes}`, кадры одним видом `IMG`); при отладке — ещё `dbg` (правда о мире) |
| `fault` | `where, text, stack` | сбой хоста мира (ниже) |

Вверх: `{t:'up', bytes}` — байты команды (§4); `{t:'speed', v}`. Всё с `st` (в воркере 0, на сервере — платформа оператора, клиентское значение не учитывается). Сетевые сообщения (`hello`/`welcome`, `ops`, `echo`, `busy`, `stopped`) — `server.md`. Только при отладке: `{t:'cfg', k, v}`, `{t:'tp'}`, `{t:'peek', unit}` → `{t:'peekImg', img}` (рендер 64×64 мимо канала), `{t:'level', canyon, pois}` (правда о мире для карты шторки).

Показания модема — то, что терминал знает о собственной линии: по каналу не идут и байт не стоят. Часы консоли идут за станцией: поправка из `modem.at`.

### Сбои

- **Терминал.** Исключение в коде консоли при приёме (декодер пакета, показания модема) ловится в `transport.onmessage` и пишется в журнал строкой `терминал: сбой приёма pkt DESC М1 — …`; туда же — `error`/`unhandledrejection` окна. Плашка «⚠ сбой ×N» в шапке открывает панель «Сбои терминала» (стек, «скопировать»). Пакет при этом принят и учтён в `rxN` — станция и канал ни при чём.
- **Хост мира.** Исключение в такте (`tick`) или в обработке сообщения (`handle`) мир не останавливает: запись `fault` в лог мира (§12) и `{t:'fault'}` всем консолям — в ту же панель с подписью «хост мира». Одна ошибка — не чаще раза в 5 с. Воркер ловит свои `error`/`unhandledrejection`, сервер — `uncaughtException`/`unhandledRejection` процесса.

Один байт в пакетах; диапазоны — `IDS` в `codebook.js`.

| id | что |

Положение своей платформы консоль узнаёт из паспорта (`INFO`, строка `платформа: x, y; курс d°`).

## 2. Канал: два плеча

**Плечо 1, локальное** — радио миссионер ↔ узел. Узел — сама станция или включённый ретранслятор на её канале (§6); мир выбирает для тела лучший (`bestNode`: наименьшее FSPL + L_преп − G_узла) и отдаёт каналу расстояние, затухание и усиление до него.

```
FSPL(d)  = 20·log10(d) + 20·log10(f_МГц) − 27,55         f = 430 МГц, d — до узла
SNR      = P_tx + G_мис + G_ст + G_узла − FSPL − L_преп − N
           P_tx  = −10…+10 дБм (регулируется, ест заряд)
           G_мис = −5 дБи (имплантированная антенна), G_ст = +6 дБи
           G_узла: станция 0, стационарный ретранслятор +6 дБ, переносной 0
           L_преп: расщелина — 8 дБ у входа + 22 дБ·глубина (доля пути вдоль дна);
                   между телом и узлом — разница их затуханий
           N     = −92 дБм (тепловой −130 + NF + помехи от реактора)
C_лок    = B · log2(1 + SNR_lin) · 0,5 · (FEC ? 0,5 : 1)   B = 4 кГц
           ниже SNR = −5 дБ несущая не захватывается: C = 0
BER      = 0,5 · erfc(√SNR_lin)   с FEC: SNR + 5 дБ
PER(n Б) = 1 − (1 − BER)^(8n)
```

Каждое удвоение расстояния — −6 дБ. Ориентиры (`act1`, 0 дБм, узел — станция): у шлюза SNR ≈ 48 дБ; вход в расщелину (400 м) ≈ 16 дБ; середина расщелины ≈ −4 дБ — на пороге захвата; глубина ≈ −15 дБ — связи нет. С ретранслятора на мачте (+6 дБ, 360 м) и передатчиком +10 дБм глубина ≈ +4 дБ, с FEC 1,7 кбит/с.

**Плечо 2, дальнее (СВС)** — станция ↔ оператор. Расстояние не влияет, ёмкость фиксированная: **512 бит/с** (настройка комнаты 512…4096; в отладке 64…16000). Битовые ошибки 1e-7. Окно видимости орбитального ретранслятора (для варианта без СВС) есть, по умолчанию выключено.

Пакет доставлен, когда прошёл оба плеча: у станции буфер (store-and-forward). Потери считаются по локальному плечу для пакетов миссионеров и по дальнему для пакетов станции.

**Несущая.** Канал каждый такт сообщает миру, кого станция слышит и с каким SNR. Тело знает это само (физика) и по инструкции (команда 26) действует после `LINK_LOST_S` = 5 с тишины. Команды телу без несущей не доставляются (событие 25).

## 3. Пакеты и планировщик

```
заголовок 8 Б: msgId(2) kind(1) unit(1) seq(2) total(2)
полезная нагрузка ≤ 64 Б
```

Классы:

- **bg** (подписки) — очередь по ключу `unit:kind`, хранит одно сообщение: свежее вытесняет недоставленное старое. Кадры (`IMG*`, `IMD*`): пока предыдущий не ушёл целиком, новый не принимается — иначе дельты теряют опору.
- **cmd** (ответы на команды и события) — одна очередь. Потерянные пакеты повторяются через RTT (ARQ, до 6 раз), повтор встаёт в начало. Пакеты тела вне зоны пропускаются — head-of-line blocking по нему нет.

Такт 100 мс. **Порядок — лестница, без квот**: на каждый пакет — верхняя ступень, где есть что отправить.

| ступень | что | внутри ступени |
|---|---|---|
| 1 | события (`EVT`); событие-следствие ответа (`after`: «задача ПС-7 закрыта» по прочитанной записи) — на ступени 3, за ответом | по порядку |
| 2 | пульс станции (`HB`) | — |
| 3 | ответы на запросы, кроме кадров: `DESC`, `SONAR`, `EXAM`, `ACT`, `CONT`, `INFO` | по порядку |
| 4 | телеметрия (`TLM`) | по кругу между телами |
| 5 | прочие подписки: описание и лидар по интервалу | по кругу |
| 6 | кадры по запросу | по порядку |
| 7 | автосъёмка | по кругу |

- Пакеты ≤ 72 Б: срочное вклинивается между пакетами большого, большое идёт остатком полосы. Если подписки просят больше канала, кадры не пройдут — это видно в очереди модема, решает оператор.
- Планировщик ждёт бюджета на пакет верхней ступени и не обгоняет его мелкими снизу: иначе при пяти телах с секундной телеметрией пульс не получал бы слота.
- ETA ответа — всё в очереди на ступенях выше плюс своя ступень до последнего пакета (`etaFor`).
- Бюджеты — token bucket: дальний и по одному на миссионера. Ведро не копит ёмкость, пока канал молчит (max 0,3 с), но вмещает минимум два пакета — иначе большой пакет на слабой линии не уйдёт никогда.
- Проверка — `tools/channel-check.js`.

**Вверх** (консоль → мир): команды 3…7 байт, задержка RTT/2 = 0,3 с, нужно живое дальнее плечо. Полоса вверх не моделируется: направления независимы, забитая очередь вниз задерживает только *ответ*.

## 4. Протокол вверх (команды)

| код | байты | смысл |
|---|---|---|
| 1 | `[1,0,unit]` | описание (нужно живое тело) |
| 2 | `[2,tilt+90,unit]` | лидар; наклон −45…+45° к горизонту (0 во втором байте — горизонт, старый формат). Наклон запоминается для автосъёмки |
| 3 | `[3,level,unit,delta]` | кадр: уровень 0…3, дельта 0/1. `unit=0` — камера шлюза |
| 6 | `[6,0,unit,xh,xl,yh,yl]` | идти в точку; тело идёт и смотрит туда. Цель за ПС-2 (§6) — событие 28 |
| 7 | `[7,mode,unit]` | режим: 1 исследование, 3 отступление (бегом к шлюзу), 4 отдых. 2 и 5 не принимаются (скрытность — 24, бой — 25) |
| 8 | `[8,objId,unit]` | взаимодействовать: подойти и выполнить действие для текущего состояния объекта |
| 9 | `[9,dBm+20,unit]` | мощность передатчика (−10 / 0 / +10 дБм) |

| 11 | `[11,0,0]` | статус станции: паспорт (`INFO`) + пульс. Этим начинается сеанс |
| 12–14 | `[k,interval,unit]` | подписки: телеметрия / лидар / описание, 0 = выкл |
| 15 | `[15,interval,0]` | пульс станции |
| 16 | `[16,interval,unit,level,delta]` | автосъёмка; `unit=0` — камера шлюза |
| 17 | `[17,0,unit]` | стоп (цель остаётся) |
| 18 | `[18,0,unit,xh,xl,yh,yl]` | смотреть: повернуть голову к точке, не идя |
| 19 | `[19,objId,unit]` | изучить: подойти и доложить состояние объекта |
| 20 | `[20,itemId,unit]` | использовать предмет: 40 брикет → глюкоза +50, электролиты +20 |
| 21 | `[21,itemId,unit,dir]` | обмен со складом у шлюза (в 12 м от люка): dir 0 — сдать, 1 — взять. 44 планшет сдан — в паспорте «планшет на складе», заметка `goal` |
| 22 | `[22,itemId,unit,objId]` | положить предмет в контейнер; objId 0 — сбросить на грунт: возникает свёрток (id 100–119) |
| 23 | `[23,itemId,unit,objId]` | взять предмет из контейнера; объект-предмет (`pickup`: планшет 32 → предмет 44) — objId самого объекта, он уходит в состояние `gone` и исчезает из описаний, лидара и кадра |
| 24 | `[24,on,unit]` | скрытность — настройка тела (§6) |
| 25 | `[25,stance,unit]` | стойка при контакте: 0 пассивно, 1 бегство, 2 бой (§6) |
| 26 | `[26,v,unit]` | инструкция на потерю несущей: 0 продолжать, 1 стоп, 2 к шлюзу |
| 27 | `[27,0,unit,idHi,idLo]` | отменить запрос: буфер станции выбрасывает непереданные пакеты сообщения `msgId` и его повторы ARQ. До мира не доходит — операция канала; ушедшие байты не возвращаются. Отменён кадр — мир сбрасывает базу дельты. `msgId` консоль берёт из очереди модема |
| 28 | `[28,on,id]` | турель своей платформы вкл/выкл; подтверждение — пульсом и событием 40 |
| 29 | `[29,on,id]` | ретранслятор вкл/выкл — только слышимый станцией (есть в пульсе), иначе событие 2; подтверждение — пульсом и событием 42 |

Координаты — дециметры, смещение +32768, big-endian (16 бит: ±3276 м, шаг 0,1 м); в пакетах вниз координата за пределом обрезается по краю.

| `CONT` | cmd | 2 + n Б | содержимое контейнера: id, n, предметы. После осмотра, вскрытия, положить/взять |

Размеры с заголовками: телеметрия 24 Б, лидар 87 Б, описание 14 объектов ≈ 230 Б, осмотр ≈ 40–80 Б, кадр 32×32 пирамидой 1376 Б, 64×64 — 5536 Б, ключевой дельта-кадр 32×32 — 1234 Б.

**`TLM`, служебные байты.** Байт 7 — опасность (бит 0; бодрствующая особь в 90 м) | инструкция на потерю несущей (биты 1–2). Байт 15 — режим (биты 0–2) | скрытность (8) | стойка (16, 32) | рефлекс (64 бой, 128 бегство). Координаты в пакете нужны, потому что к моменту доставки тело уже ушло.

**`HB`, пульс платформы.**

- Заголовок: биозапас, камеры на складе, рост (с или 255), брикеты на складе, резаки на складе.
- n — только свои тела, по 9 Б: id; флаги (жив, несущая, камера, лидар, автосъёмка, у шлюза); заряд; предметы (биты 0–1 — число брикетов, 2 — резак, 3 — патроны, 4–5 — передатчик: 0 −10, 1 0, 2 +10 дБм, 3 иное; 6 — планшет); SNR+30 дБ (станция измеряет уровень каждого тела; без заряда передатчик молчит); подписки тела — интервалы телеметрии, лидара, описания (с, 0 — выкл) и автосъёмка одним байтом (биты 0–4 интервал, 5 дельта, 6–7 уровень).
- Байт автосъёмки камеры шлюза.
- m — свои турели, по 3 Б: id, флаги (0 питание, 1 включена, 2 повреждена, 3 ведёт цель, 4 перезарядка), патроны (255 — без питания, данных нет).
- r — ретрансляторы, чей маяк станция слышит на своём канале, по 2 Б: id, флаги (0 включён, 1 переносной). Нет в пульсе — не слышен; где стоит — из паспорта.

Настройки тела держит станция — по пульсу консоли одной платформы сходятся в переключателях (`syncSubs` в `console.js`).

**`INFO`, паспорт** — текст, всё про свою платформу: блок (`ARK-04k`), состояние, возраст миссии, оператор, `платформа: 180, −150; курс 0°`, запасы, `возврат: ПС-2, 500 м от узла; узлов 1`, турели (`турели: 230 (22, 0) курс 0° сектор 140° дальность 120 м; питание 40 м от корпуса`), канал и ретрансляторы в сети (`канал 1; ретрансляторы: 7 (124, −77) стационарный, дальность 2000 м, +6 дБ, включён` или «нет»; та же строка приходит отдельным `INFO` при событии 3), задача. По строкам платформы, возврата, турелей и ретрансляторов консоль рисует корпус, сектора, узлы и круги возврата.

**`EVT`, коды событий** (полный список с текстами — `EVENTS` в `codebook.js`; здесь — те, у которых значим аргумент или адресат):

**Текст по каналу.** Описания, осмотры и результаты действий — текст, который станция составляет из базы знаний и состояния мира (`nameOf`, `examText` в `world.js`): «тело М1», «существо, класс не определён», «Не двигается. Камеры нет. При нём: резак». Заранее на стороне консоли ничего не перечислено. Кодировка однобайтовая, в духе КОИ-8 (`encText`/`decText`): байт на символ. Многопакетные сообщения собираются по `msgId` (`assemble`). Коды остаются только у событий, режимов и предметов — это протокол.

**База знаний станции** (`codebook.js`) живёт в мире: логика состояний и шаблоны текста.

- Корпоративную номенклатуру (`corp`: люк, прожектор, ящики, кабели, мачта, шкаф, планшет, свёрток, турель, ретрансляторы) станция знает заранее: в описании идёт номер типа, консоль по нему и состоянию показывает именные команды (`objCmds` — одна функция для консоли и `opconsole`; источники — `cmds` у типа, `actions[].cmd`, `accepts`, `afterExam`). Природное и неизвестное — тип 0 и одна кнопка «взаимодействовать».
- Консоль берёт из кодовой книги только кодек текста, коды событий, режимов и предметов.
- Типы: 1 — шлюз платформы (2…9 свободны после формата 2), 10…36 — объекты (32 планшет, 33 свёрток, 34 турель, 35/36 ретрансляторы), 250 — неизвестный, 251 — тело миссионера, 252 — живой миссионер.
- У типа: `states[]` — текст по состояниям (ответ на «изучить»); `actions[]` — `{from, to, verb, item?, needs?, req?, fail?, special?}`: переход, глагол для журнала, выдаваемый предмет, требуемый предмет, требуемое состояние другого объекта, текст отказа. Тип с полем `relay` — ретранслятор: состояние и осмотр составляет мир (§6).
- Предметы: 40 брикет, 41 резак, 42 камера (становится датчиком), 43 патроны, 44 планшет.
- Пример зависимости (`act1`): резак (в свёртке у мачты) → срастить кабель (id 8) → у ретранслятора (id 7, `feed:{obj:8,state:1}`) появляется питание → тело включает его и настраивает на канал станции.

**Контейнеры.** Тип с полем `container: k` — содержимое видно и доступно с состояния k (ящик — после вскрытия, груда — после разбора, свёрток и тело — всегда). Мир хранит `contents[id]`; у тела — его предметы плюс камера (42). Передача между миссионерами — только через контейнеры.

**Рядом.** Описание издалека отдаёт только тип; «изучить» и «взаимодействовать» требуют подойти (`pending`: тело идёт, по прибытии выполняет). «Рядом» — одно число `REACH` = 1 м до поверхности: точки указателя, стенки коллайдера, центра предмета без коллайдера. Тело идёт к точке в 0,8 м от стенки со своей стороны (`reachPoint` через `outsideHulls`). Указатель на «изучить» отдаёт свой текст из карты; действий у него нет. Консоль ведёт **журнал** по объектам — текст станции как есть: «М1 · ящик: вскрыл. Вскрыт. Здесь: пищевой брикет.»

## 6. Мир

Такт 0,1 с; ускорение ×1/×2/×4 применяется к миру и каналу одновременно.

### Уровень

Карта — `proto/maps/ID.js`, объект `LEVEL`, формат 2; данные акта, отдельно от логики. Сейчас две: `act1` (первый акт, 1…4 платформы) и `duel` (две станции, цепочка ретрансляторов к планшету; геометрия — `brief-duel.md`, прогон — `tools/duel-check.js`).

- `meta`: `id` (равен имени файла), `name`, `v` — ревизия (редактор поднимает при сохранении; сохранение комнаты и запись `start` лога её помнят), `format` — должен равняться `LEVEL_FORMAT` (`levelCheck`: одна проверка на сервер, воркер, редактор, спектатор и tools; мир с картой чужого формата не поднимается; формат 1 переводит `tools/level-convert.js`).
- Хост выбирает карту по id: одиночная игра — `index.html?map=ID` (сохранение и лог в браузере — свои на каждую карту), комната — `cfg.map`.
- **Слои** (`design.md` §11г):
  - `terrain` — расщелина (колена и ширины, отросток), край `bounds`, пятна рельефа `bumps` {x, y, r, h};
  - `sites`, `layouts` — площадки и раскладка (§1 «Платформы»);
  - `pois` — **указатели**: место с именем и текстом осмотра, без спрайта и действий;
  - `objects` — **объекты**: абсолютные координаты, id 1…99, тип, курс, начальное состояние, содержимое, у ретранслятора — `on`, `freq`, `powered`/`feed`, `range`; `collider` {r, h} переопределяет коллайдер типа; `scenery:1` — **примета** (флаг читает только редактор, мир разницы не видит);
  - `decor` — спрайт в кадре и отражатель лидара, в описании и на карте его нет; с `collider` — не пройти;
  - `pack` — стая: логово, особи с лёжкой и чертами, не больше 6.
- `world.js` строит из уровня `POIS`, `OBJS`, `HULLS`, `relays`, `objState`, `contents`, `pack`; `terrain.js` — расщелину, хребет, пятна и `FIXED`; производные пересчитывает `TER.reload()`.
- Видимость по расщелине — из геометрии (`TER.inside`, `tunnelT`): изнутри видно только то, что в расщелине (тело до 1 м за кромкой дна — тоже внутри; объекты у стены ставить на дно); глубокое (дальше 5 % пути) снаружи видно лишь в 30 м от входа.
- Файл пишет редактор сериализатором `levelText` (детерминированно). Правила, которые не мешают поднять карту, — `levelLint`: объект внутри чужого коллайдера или корпуса, объект без спрайта, примета с действиями, указатель без текста, особей больше 6.
- Свойства типов (спрайт, коллайдер, высота отражателя, радиус для лидара) — в `codebook.js` и `world.js`, не в уровне.

### Рельеф, декор, коллайдеры

- **Рельеф** (`terrain.js`, `TER`) — одно поле высот `H(x,y)`: равнина с дюнами, посадочное поле под площадкой 1 (`landing` от `LEVEL.sites[0]`; остальные платформы стоят на естественном рельефе), хребет, **расщелина** — ломаная из колен с отростком (`LEVEL.terrain.canyon`), вырезанная до дна, в конце — завал; пятна `bumps` — купола `h·(1 − smoothstep(d/r))` (яма при h < 0). `tunnelT(x,y)` — доля пути вдоль дна (0…1) или −1 снаружи: от неё считаются затухание радио, токсины и темнота. Дизайн местности — `design.md` §11б.
- **Край уровня** (`bounds`, `inBounds`): дальше рамки тела и одичалые не ступают, телепорт обрезается. Техническая гарантия, не игровое правило.
- **Декор** (`TER.decor`): процедурный — по хешу координат (валуны, россыпи, сухостой, выходы породы, останцы); из уровня — `LEVEL.decor` (`FIXED`). Попадает в кадр и лидар (`DECOR_R`), в описание и на карту — нет. Процедурные валуны и выходы выше 0,8 м — стена (`solidDecor`); декор уровня с `collider` — в `HULLS`.
- **Коллайдер** (`objCollider`): круг {r, h} у типа или экземпляра; объект без коллайдера — предмет, через него проходят, лидар видит его по `SONAR_R`/`OBJ_H`. Одно свойство на всё: ходьба (`blocked`), лидар (`rayHull`), обзор (`losFrac`), точка подхода (`outsideHulls`).

### Миссионер

- Состояние: позиция, курс (направление последнего движения), цель `goal`, движение `target`, режим, настройки, тело, датчики, подписки, `lastImg` по уровням для дельт.
- Тело — несколько ОДУ: пульс (нагрузка, страх, боль), глюкоза, электролиты, токсины в расщелине, психика (страх, темнота), заряд = (генерация − потребление)·0,01/с. Заряд 0 — смерть.
- **Мёртвое тело** остаётся; приборы работают на остатке заряда (утечка 0,004/с, 0,03/с при автосъёмке). Телеметрию чаще раза в 30 с станция при смерти переводит на 30 с. В описаниях других — тип 251, контейнер.
- **Режим** `mode` (команда 7): исследование, отступление к точке старта, отдых.
- **Скрытность** `stealth` (команда 24): фонарь выключен, медленный шаг, шум шагов ∝ v²; одичалые видят с 6 м вместо 70.
- **Стойка** `stance` (команда 25) и **рефлекс** `reflex` — что тело делает по стойке сейчас (`stanceTick`, `contact`). Реакция на одичалого решается телом: канал для неё слишком медленный. Пока рефлекс идёт, фонарь горит (`lightOn = !(stealth && !reflex)`).
  - Контакт — глазами тела без стены (`losFrac` < 0,34) или укус за последние 3 с.
  - *Бегство* (1): тело бежит к ближайшему узлу — в расщелине вдоль оси наружу, снаружи прямо; у узла контакт бегства не начинает (заметка `бегство не начато`).
  - *Бой* (2): угроза — особь, идущая на тело или нападающая, рядом; тело останавливается, бьёт ближайшую особь (`fightBack`), без угрозы возвращается к цели.
  - Пассивно (0): тело ничего не делает. Прогон — `tools/pack-check.js [шаг] [стойка]`.
- **Инструкция на потерю несущей** `autonomy` (команда 26): после 5 с без несущей — продолжать / стоп / к шлюзу.
- **Возврат к шлюзу** (инструкция «к шлюзу», режим «отступление») — `homing`: в расщелине цель пересчитывается по оси к выходу (`waypointOut`), снаружи — прямо к точке старта. «Идти» и «стоп» снимают.
- Консоль показывает режим, стойку, скрытность и инструкцию только из телеметрии; запрошенное, но не подтверждённое — пунктиром, снимается через 90 с.

### Движение и обход

- Тело (радиус 0,6 м) не идёт на склон круче `MAX_SLOPE` = 40° и сквозь корпуса (`HULLS`: эллипс платформы, коллайдеры объектов и декора). Цель внутри корпуса переносится на ближайшую точку снаружи; при упоре шаг поворачивается на ±45°/±90°.
- **Обход в пределах видимого** (`planLocal`): карты мира у тела нет, оно видит вокруг `SEE_R` (без фонаря `SEE_DARK_R`). Прямо проходимо (`walkLine`) — идёт прямо; иначе A* по сетке 0,5 м в круге обзора, путь натягивается нитью. План годен, только если приближает к цели на `PLAN_GAIN` сильнее, чем тело уже бывало; иначе стоп, «путь перекрыт» (заметка `path`).
- Страховка: за 4 с не сдвинулось или за 30 с не приблизилось на метр — стоп (заметка `stuck`). Тупики и обход хребта — работа оператора: расщелина проходится точками по коленам.
- Одичалые ходят с теми же столкновениями и обходом (видят на `SEE_DARK_R`); в расщелине — по её оси (`packStep`).

### Датчики

- **Камера** (`camera.js`, `CAM`): смотрит на цель, если она есть и не достигнута, иначе по курсу. Поле зрения 50°, глаза 1,6 м. Рэймарчинг по полю высот (солнце снаружи, фонарь в расщелине, без фонаря — ближний метр; дымка), объекты и декор — спрайты-билборды из атласа (`SPRITES` в `codebook.js`: 5 ракурсов + зеркало, высота в метрах; курс объекта выбирает ракурс, состояние подменяет лист). Рендер в удвоенном разрешении с усреднением. `renderRaw(u,W,objs,{H,fov,heading,z})` — кадр другого размера и ракурса для `tools/banner.js` и свободной камеры редактора. Атлас и генерация — `art.md`.
- **Лидар** (в коде и протоколе — `sonar`/`SONAR`, историческое имя): 64 луча с высоты `SONAR_H` = 1,7 м под наклоном `u.sonarTilt`; луч (`castRay`) идёт по полю высот шагом 0,5 м с уточнением бисекцией, дальность наклонная. Корпуса и объекты без коллайдера отражают по высоте (`OBJ_H`): луч выше проходит.
  - Бит «сплошное» — измерение, не подсказка мира: на каждый азимут второй луч на `SONAR_DT` = 3° выше; хорда между двумя попаданиями круче `MAX_SLOPE` — «сплошное». Склон, взятый наискось, кажется положе; второй луч без эха — не сплошное.
  - Наклон вниз даёт эхо от грунта на каждом луче — профиль рельефа. Снимки из соседних точек сходятся в пределах шага квантования дальности (0,4 м).

### Граница мира (ПС-2)

Протокол станции, не физика линии и не рельеф. Цель команд «идти», «изучить», «взаимодействовать», «положить», «взять» дальше `RETURN_R` = 500 м от ближайшего **узла** станция не принимает — событие 28; тело остаётся как было. Цель ближе к узлу, чем тело сейчас, принимается всегда — тело за чертой может отступить. Узлы — центр станции и включённые ретрансляторы на её канале (`nodes(S)`). Бюджет линии к границе не привязан: несущая за ней может держаться.

### Ретранслятор

`relays[]`, `relayTick`; объект уровня типа 35 (стационарный) или 36 (переносной). К базе не привязан — общий для всех платформ.

- Поля в уровне: `on` — включён на старте; `freq` — канал (0 — не настроен); `powered` — питание (нет поля — автономно); `feed:{obj,state}` — питание, пока объект в этом состоянии; `range` — дальность линии до станции (иначе паспортная: стационарный 2000 м, переносной 400). Усиление антенны — по типу (`CODEBOOK[тип].relay`).
- **Канал** станции `S.freq` = 1 + номер команды: ретранслятор на канале слышат все станции команды.
- Станция **слышит** ретранслятор (`reach[k]`), если есть питание, `freq` совпадает и до станции не дальше `range`: он в пульсе и переключается командой 29. Включённый слышимый — **узел** (`linked[k]`): линия тел считается до лучшего узла (§2), от ближайшего — ПС-2 и бегство.
- **Тело вплотную**: без питания — отказ (код 3); выключенный — настраивает на свой канал и включает; включённый на своём — выключает; на чужом — перестраивает на свой (у чужой станции узел пропадает, событие 41).
- Состояние объекта: 0 выключен, 1 включён, 2 без питания. События 3/41/42, заметки `relay` (§12).
- Дальность — паспортное число линии, не мощность: при честном FSPL любой передатчик добивал бы на десятки километров.

### Турель

`turrets[]`, `turretTick`; объект типа 34, id 230+k, владелец `st`. Числа — константы в `world.js` и `BASE.turret`; дизайн — `design.md` §8а.

- Штатная у каждой платформы (6 м перед шлюзом, сектор наружу); площадка может задать свою (`site.turret`: dx, dy, f, fov, range, aim, reload).
- **Питание** — зона `STATION.powerR` от корпуса своей платформы; вне зоны турель слепа, в пульсе — «данных нет».
- Лампа турели видит только освещённое: сектор, дальность, без стены. Захват — по движению (стоящее не захватывается): одичалые и тела чужих команд. Прицел `aim` с; цель вышла из сектора или за камень — захват сброшен. Точность 100 %, насмерть.
- **Патроны**: магазин, ёмкость `AMMO_MAX`, перезарядка; пусто — наводится и светит, не стреляет (событие 38). Пополняет тело: «положить патроны (43) в турель» вплотную.
- **Состояния**: включена / выключена / повреждена. Своя переключается телом или командой 28; свою сломать нельзя. **Чужую режут** резаком (`CUT_S` вплотную): турель разворачивается на режущего и, если включена и с патронами, стреляет первой; иначе сломана (событие 39).
- Для стаи: освещённая особь чувствует луч и при низком `nerve` бежит от света; выстрел слышен далеко (страх, настороже; телам — `startle`). Турель — ориентир для агента стаи.
- **Команды платформ** — параметр комнаты `?teams=0,0,1,1` (`S.team`); нет — каждая платформа сама за себя. Мир не знает, кто с кем: турель сравнивает команду цели со своей, одичалые чужие всем.

### Одичалые

Дизайн, рефлексы и таблица реакций на крики — `design.md` §12а; числа — блок «одичалые» в `world.js`. Здесь — механика и что видит оператор.

- Стая `pack` из особей уровня. Особь: черты `size`, `courage`, `attention`; состояние `hp`, `fear`, `tired`, `act` (sleep / idle / freeze / approach / attack / back / flee / home / rest / goto / dead), `foe` — чужой, которого видела или слышала недавно.
- **Храбрость** `nerve(p)` — одно число из черт, страха, ран и удалённости от логова; по нему выбирается рефлекс (бегство, отход, наблюдение, подход, нападение). Поводок к логову — следствие формулы.
- **Чувства** раз в 0,5 с: зрение — `detectRadius(тело)` (фонарь, отдых, скрытность), слух шагов ∝ v²; стены — `losFrac(a,b)` (доля отрезка на высоте 1,2 м, закрытая рельефом или корпусом).
- **Удар**: вплотную раз в 2 с — кожа, кости, боль, психика, событие 4. **Отпор**: тело в рефлексе «бой» бьёт ближайшую особь; на нуле hp особь бежит (событие 9), удар по особи с hp 0 — смерть (`killPack`), событие 43.
- **Крик** (`cry`): слово из шести (тревога, чужой, сюда, бей, домой, добыча), радиус по размеру, ослабление стенами. Реакция держится `hold`, пока особь сама не увидит чужого или не дойдёт. Тела в радиусе получают `startle` → страх → пульс; слов не разбирают.
- **Для оператора**: бит опасности телеметрии; страх тела — от близости бодрствующих особей плюс `startle`. В описании — «объект, класс не определён» (спит) или «существо, класс не определён»; осмотр называет размер и что делает; лидар — отражатель по размеру; в кадре — лист по состоянию.

### Агент стаи

`world.js`, блок «агент стаи»; спека для агента — `agent-pack.md`, HTTP — `server.md`.

- Одна ось — `VOICE_R`, радиус голоса стаи (`?voice=N`; по умолчанию ∞ — восприятие каждой особи и слово каждой; конечный радиус не сделан). Особи — О1…О5 по порядку в уровне.
- **Восприятие** — `perceive(p)` раз в 0,5 с после рефлексов: строка **на смену класса**, не по таймеру. Наружу `{t:'agent', n, at, who, text}`: станция отдаёт хосту агента (`opts.agent`) и в лог, консоли не видят. Полная картина — `agentState()`.
- В тексте нет координат, метров, номеров тел и карты (имена тел для стаи — `packName`: «двуногий»); отладочный флаг сюда не достаёт.
- **Намерения** — `intent('О2: к обломкам')` → `{t:'agentAck', ok, who, why}`. Кулдаун на особь `INTENT_CD` / `INTENT_CD_SHORT`. Принятое слово (`p.told`) ложится в те же `goto`/`freeze`; рефлексы главнее. Принято ≠ выполнено: что сделано — в ленте.
- Площадка — `tools/agent-play.js`: станция в node без сети, лог мира → `data/play-*.log`.

### Агент-оператор

`server/opconsole.js`; спека — `agent-op.md`, HTTP — `server.md`. Виртуальная консоль — такой же клиент комнаты, как браузерная (`OpClient` проходит `join`/`hello`/`handle`/`leave`). Декодирует пакеты в строки журнала (телеметрия и пульс — на перемену; описание, лидар-сводка, кадр текстом 32×16, события, осмотр, действие, содержимое, паспорт, потери) и переводит текстовые команды в байты §4. Знание — только из пакетов: `known` по съёмке + пеленг + дальность; свои тела — из телеметрии (`ownKnown`). Названный номер, которого нет в `known`, — ошибка разбора, а не похожее имя. Мир и станция разницы с браузером не видят.

## 7. Изображения: подтверждение кадра

Дельта-кадр опирается на последний кадр, который *реально ушёл*. Мир не знает состояния канала, поэтому:

1. мир рендерит кадр, кладёт его в `pendingImg`, шлёт `IMD`;
2. канал принимает (нет незавершённого кадра того же тела) и отвечает `imgAck ok=true` либо отбрасывает — `ok=false`;
3. мир обновляет `lastImg` только при `ok=true`.

Кадры по кнопке (класс cmd) очередь принимает всегда, `lastImg` обновляется сразу.

Консоль собирает кадр по пакетам; сборка живёт, пока приходят пакеты (90 с без пакетов — сброс). Блок на границе потерянного пакета не применяется. Новая пирамида чистит холст; дельта — нет.

## 8. Консоль

Никакой логики мира в консоли нет; всё, что похоже на знание, — кэш принятых пакетов. Три источника изменения на экране: запрос (свой или эхо сокомандника, `server.md`), состояние (`TLM`, `HB`), причина (`EVT`).

- **Состояние по телу**: телеметрия и история, трек, последний лидар, описание, кадр, подписки, цель, инструкция.
- **Карта объектов** — из описаний: координаты съёмки из пакета + пеленг (шаг 2°) + дальность (шаг 1 м). Ошибка растёт с дальностью, поэтому для неподвижного объекта остаётся оценка с самой близкой съёмки (`range` в `known`); существо — всегда свежая. `seenBy` — кто видел; изученный или тронутый объект тоже знаком. Треки — из телеметрии, до 600 точек.
- **Стены** (`wmap`): сплошные отсчёты лидара, соседние с разницей дальности < 0,5 м + 30 %, соединяются отрезком и растеризуются в ячейки 0,5 м с числом попаданий. Двадцать снимков одной стены дают одну линию.
- **Карта высот**: из дальности, наклона и высоты датчика — высота каждой точки попадания, сетка 2 м (среднее, до 8 отсчётов веса). Сплошные отсчёты в неё не идут: точка на вертикальной поверхности — не высота грунта в этой XY. Ячейки, через которые прошла стена (`hwall`), — граница: сглаживание через них не тянется, изогипсы в таких квадратах не строятся. Изогипсы через 0,5 м (marching squares), цепочки короче 4 отрезков не рисуются. Точность — `tools/hmap-check.js`: медиана ошибки ячейки 0,03 м. Увязка снимков по перекрытию проверялась и отвергнута — при барометре 0,1 м она только добавляет дрейф.
- Сами снимки лидара консоль не хранит — только последний на теле; карта высот и растр стен — в сохранении (`hmap`, `walls`).
- **Радиус возврата** — круги вокруг узлов: радиус и места — из паспорта, включённость ретрансляторов — из пульса. Сдвиг карты ограничен радиусом возврата от всего, что консоль знает.
- **Расход по панелям** — скользящее окно 5 с по доставленным байтам каждого вида. Оценка под кнопкой «снять» — из размеров §5 и текущей ёмкости.
- Данные старше порога приглушаются (`.stale`): тело — 3 интервала телеметрии, лидар и описание — 120 с, кадр — 300 с.

## 9. Сохранение

Одиночная игра: `localStorage['missioners.save'] = {v, savedAt, world, console}` каждые 10 с (после открытия консоли) и при экспорте. `v` = `SAVE_VERSION`; при расхождении заставка предупреждает и советует новый сеанс.

- **Мир**: `snapshot()`/`restore()` в `world.js` — время, станция, состояния объектов, стая (по индексу особи), миссионеры (без буферов кадров), усиление. Игровое время стоит, пока консоль закрыта (`catchUp` вызывается с 0); скрытая вкладка — не пауза.
- **Консоль**: `consoleSnapshot()`/`restoreConsole()` — время, активный, станция, счётчики, миссионеры (история до 600 точек), `known`, `journal`, содержимое контейнеров, карта высот и растр стен, лог (400 строк).
- Меню сеанса — в терминале заставки: `[r/enter] resume [n] new [i] import file [e] export file`. Экспорт — тот же JSON файлом.
- После восстановления заставка всё равно проходит через реальный запрос статуса; очереди канала сбрасываются (`link.reset()`).

Сетевая игра: мир хранит сервер (формат файла комнаты — `server.md`); консоль хранит в браузере только своё знание (`missioners.save:КОД:k`, `world:null`) и `rxN`, остальное досылается пакетами.

## 10. Сетевой хост

`server/index.js` — Node: комнаты, лобби, WebSocket консолей и зрителей, HTTP для агентов, хранение. Всё это — `server.md`. Контракт с миром тот же, что у воркера (§1): станция, строка `search`, сообщения с `st`. Сетевой хост ничего не толкует в мире — параметры комнаты (`n`, `teams`, `voice`) уходят в строку мира. Отладки на сервере нет: `cfg`/`tp`/`peek`/`speed` от клиентов игнорируются; локальный сервер с `debug` ведёт себя как одиночная игра.

## 11. Инструменты

Редактор уровня, спектатор, лаборатория лидара, отладочная шторка — `tools.md`. Инструменты читают мир напрямую; правило «консоль не читает мир» на них не распространяется. Редактор и лаборатория работают только на localhost.

## 12. Лог мира

Полная запись сеанса для спектатора и разбора «что шло не так». Точка одна — `station.js`: через неё проходит всё, что входит в мир и выходит из него. Хост даёт `opts.log(rec)`, станция добавляет `t` (часы мира) и зовёт его. Формат — JSONL, поле `k`:

| `k` | что | откуда |
|---|---|---|
| `start` / `restore` | начало лога (хост, число платформ, карта `map:{id,name,v}`, стенное время) / мир восстановлен | хост / станция |
| `op` | оператор вошёл / вышел (имя, платформа, `since`) | сервер |
| `up` | байты аплинка (`st`, `bytes`) | станция |
| `pkt` | доставленный пакет: `st`, `n`, `kind`, `unit`, `id`, `seq/total`, байты `b` в base64 | станция |
| `drop` | потеря с причиной | станция |
| `speed`, `cfg` | ускорение, отладочные крутилки канала | станция |
| `phys` | раз в секунду мира — правда о мире целиком (`truth()`): тела, особи (с `nerve`, словом агента, `why`), турели, свёртки, SNR по телам, станции (биоматериал, выращивание, склад, питание, канал, задача) | станция из `dbg` мира |
| `agent` / `agentAck` | лента восприятия стаи и ответы на намерения | станция |
| `note` | заметка мира (ниже) | `note()` в `world.js` |
| `fault` | сбой хоста мира: `where`, `text`, `stack` | станция |
| `pause` / `win` / `resume` / `disputed` / `archive` / `unarchive` | остановки комнаты (в старых логах — `stop`) | сервер |

**Заметки** — решения с числами, от которых они зависели: ставятся там, где `if` с числами решает игровой исход. Виды: `cmd` (разобранная команда), `pack` (заметила, сменила действие с `why`, укусила, получила удар), `cry`, `station` (отказ по ПС-2, серия закрыта), `relay` (в сети / вне сети, узел, переключён, питание, отказ команде 29), `unit` (смерть с причиной, несущая потеряна/восстановлена, инструкция сработала, путь перекрыт), `goal`, `debug`. Заметки идут **только в лог**: операторам станция их не пересылает ни в каком режиме.

**Хосты.** Сервер — `data/КОД.log`, дописывается раз в `SAVE_EVERY` и при остановке мира; выдача и живая трансляция — `server.md`. Воркер — память + IndexedDB (`missioners-log`, куски по 5 с; ключ `main`/`lab`); новый сеанс очищает лог; «лог мира» в шторке скачивает JSONL. Объём — около 1 МБ на час игры, основное — `phys` и `pkt`.

**Чтение.** `node tools/log-read.js data/КОД.log [stats | t0 t1]` — лента по игровому времени человеческим текстом и сводка (пакеты по видам и Б/с, потери, команды, крики, смерти). Разбор смыслом — поверх этой ленты, скриптом или агентом. Проигрывание — спектатор (`tools.md`).
